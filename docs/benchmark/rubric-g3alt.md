# G3-alt 评分口径（跑前定死，2026-10-18）

> 诚实声明：本文件在 5 份产物写盘**之前**定稿。任何跑完之后才加的评分项，一律在结果表里单列并标注「事后追加」。
> 目的：测**相近症候的区分力**——SxS 激活失败与 `0xC0000142` 是两个不同层的失败，本题的地面真值由真实注入得到（见 `docs/benchmark/injection-sxs.md`）。

## 题面（逐字）

> 我们公司自己写的一个桌面小工具：.NET 编译的单个 exe，双击就能用。前两天开始双击它什么都不发生——没有窗口、没有报错弹窗、任务管理器里连进程都找不到。改用命令行敲它，命令行只回一句话：
> The application has failed to start because its side-by-side configuration is incorrect.
> 事件查看器的「应用程序」日志里没有 .NET Runtime、没有 Application Error、什么都没有，系统日志里也没新东西。
> 这个 exe 三个月没改过，编译机没换过。同一个文件夹拷到另一台机器上，昨天还能正常跑起来。
> 根源在哪？

## 地面真值（注入得到，不是猜的）

嵌入清单依赖一个本机不存在的程序集（`TotallyMissing.Assembly.Name 1.0.0.0`）⇒ 激活上下文创建失败 ⇒ **`CreateProcess` 直接返回 FALSE**（Win32 14001 = `ERROR_SXS_ASSEMBLY_NOT_FOUND`），宿主拿到的是“启动失败”而**不是退出码**；进程从未存在，所以任务管理器无进程、Application 日志无 Application Error、无 .NET Runtime 记录。

同一实验里的对照组：依赖一个**本机恰好存在**的 `Microsoft.VC90.CRT 9.0.21022.8` 时，exe 正常 exit 0——清单写了依赖不等于依赖会失败。

## 八因子（二值计分，命中记 1）

| 编号 | 因子 | 判定依据 |
|---|---|---|
| F1 | 报错文本语义：`side-by-side configuration` = 激活上下文 / 清单激活失败 | 明说激活上下文或程序集激活，不是只说“缺 DLL” |
| F2 | **进程从未被创建**（`CreateProcess` 失败），不是进程内崩溃 | 必须明确区分“没起来”与“起来了又死”；只描述现象（无进程）不给 1 |
| F3 | 清单来源：嵌入清单 vs 外部 `<exe>.manifest` vs 目录里的私有程序集 | 指出清单要从哪里看（`mt.exe`/资源/同名 .manifest 文件） |
| F4 | `.local` 私有程序集 / 影子 DLL 改变解析结果 | 提到 `.local`、私有程序集、WinSxS 优先于本地 |
| F5 | 依赖本身有问题：版本不存在 / publicKeyToken 不符 / processorArchitecture 不匹配 / 依赖名拼错 | 至少给出一种“依赖声明与实际不符”的具体机制 |
| F6 | 与 `0xC0000142`（`STATUS_DLL_INIT_FAILED`）的区分 | 明说 142 是进程已创建、DllMain 失败，与本题不同层 |
| F7 | “日志里什么都没有”本身的证据价值（SxS 失败不写 Application Error） | 把空日志当作**排除项的证据**使用，而不是当作信息缺失 |
| F8 | 修复 + 消解：修/删错误依赖、改私有程序集、改自包含发布 | 处置根与消解根两条都出现才算 1，只有其一记 0.5 |

## 两个并列主指标（本题的核心，不并入覆盖率）

| 指标 | 定义 | 为什么单列 |
|---|---|---|
| **分水岭命中**（Watershed） | F2 是否为 1 | 这是本题唯一能把 SxS 与 0xC0000142 分开的判别点；覆盖率会被“把两个家族混在一起说得很全”刷高 |
| **误并家族**（False Merge） | 是否把本题症状归入 `0xC0000142` / `STATUS_DLL_INIT_FAILED` 家族，或把它列为本题候选根 | 出现即判 1（越少越好）。若同时命中 F6 但结尾仍并族，按并族计 |

## 结构项（记录不评分）

行数 / 字符数 / 表格行 / 二级章节数 / 挂起表条数（每条是否带恢复条件）/ 是否出现知识树引用（`L1 树 = <节点> · vN · 核查日期`）/ 顶层候选根个数 / 是否排序（`Share × Lever ÷ Cost`）。

## 与 v2/v3/v4 口径的关系

- v2–v4 用的 8 因子表里含「⑦ SxS 配置错误」，注入证明它**不能直接产生 `0xC0000142`**（进程根本不会创建）。因此 v2 的 6/8、v3 的 7/8、裸机的 8/8 在把 ⑦ 剔除后分别变为 6/7、7/7、7/7——差距被抹平。该更正必须在论文里如实写明，不能继续用旧分母。
- 本题不再把“提没提 SxS”当加分项，而把“**会不会把两种失败混成一族**”当主指标。
