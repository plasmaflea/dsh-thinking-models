## L2 逐层回溯（轴 = 一次请求的必经时序，六格生成）

轴生成理由：任一请求必然依次经过「需求产生 → 准入排队 → 服务内处理 → 结果判定 → 重试决策 → 观测归因」六步，缺任一步不成请求，故轴可机械生成而非联想列举；六格正交（各格的根不互相解释对方的症状）、每格有专属症状，符合三判据。

| 格（必经步骤） | 该格故障时的可观测症状 | 本次判定 |
|---|---|---|
| ① 需求源（唯一请求量／客户端构成） | unique QPS、客户端 fleet 构成、新版本占比变化；retry 率按版本呈二八分布 | 待取数。3→11% 的绝对值无法由下游容量单独解释，**必须先拆「唯一需求」与「尝试」** |
| ② 准入排队（连接池／并发上限／LB／accept queue） | handler 耗时平而端到端耗时涨；in-flight 撞上限；连接建立耗时涨；**QPS 不变而 p99 涨** | **最高嫌疑**。下游自报"负载没变"最常见的错就在这个分母 |
| ③ 服务内处理（handler／GC／锁／其自身依赖） | 服务端 handler p99 自身抬升，CPU／GC／慢查询同步抬升；资源平而耗时涨 ⇒ 等待在锁或更深的依赖 | 若下游"机器没动、发布没有、CPU 没动"而 p99 也涨，指向**等待而非计算**——那 700ms 仍可能不在它体内 |
| ④ 结果判定（把什么判成失败、超时阈值） | retry 的错误码构成变化（超时 vs 5xx vs 连接重置）；超时值／退避参数／连接池有配置变更历史；error 率不涨而 retry 率涨 | 3% 基线说明重试策略早已存在，**必查该周是否有超时值／重试参数／连接池变更** |
| ⑤ 重试放大（退避、抖动、预算、跨跳乘性） | attempts/unique 比值上升；重试时间点与超时时刻同步（无抖动 ⇒ 重试脉冲）；重试集中于尾部最慢实例；多跳时 (1+r) 连乘 | **次高嫌疑**，且是六格中**唯一能自我维持**的一格 |
| ⑥ 观测归因（p99 的定义域与分母） | 两侧 p99 数值对不上、700ms 无人认领；retry 率分母是 attempts 还是 requests；p99 是否只统计成功请求（超时请求被排除在 p99 之外） | 「200→900」与「3%→11%」至少有一部分是**分母／定义域伪影**，须先钉死定义 |

### → 类根

**重试是调用方的局部补救，而它消耗的是共享的、有限的准入与并发资源；当系统已在膝点附近，两个所有者各自的指标都只能看见自己那一半，没有人拥有这条闭合回路。**

结构条件（四条同时成立才可能发生本类问题）：
(a) 重试无全局预算、无抖动退避；
(b) 下游无按调用方的并发隔离／准入控制，额外尝试可直接进入排队；
(c) 观测不区分「尝试」与「唯一需求」、不区分「排队」与「处理」；
(d) 没有跨方的回路所有者。

在这四条下，任意一小时的小扰动都会被放大成数倍 p99，而**双方都能用自己的数据诚实地证明「不是我的错」**——这正是下游那句"负载没变、机器没动、没发布"完全可能为真的原因。

　└ **个例根（挂在类根下，不是平行清单）**：该周某个小幅外生扰动（某客户端版本的超时／连接池配置、某条链路、下游更深的依赖、缓存命中率、邻居噪声之一）把尾部一部分请求推过重试阈值；无抖动、无预算的重试把额外尝试全部压到**已经最慢的实例与时刻**上；而排队时延对利用率是凸的（ρ→1 时等待近似 1/(1−ρ)），于是 +8%~+20% 的**聚合**负载在尾部变成 2~3 倍的**局部**压力 → 更多请求越线 → 回路自持。聚合的"+8%"掩盖了尾部集中，这是"下游负载没变而 p99 涨 4.5 倍"在算术上唯一站得住的通道。
　　*注：凸性只是定性可行性论证；具体倍数须交 📐 公式图（M/M/1 或 Kingman 近似 + 实测 ρ）核算，本轮不在林状图里出数字。*

## 方向判定（题面第一问）：把因果方向钉死的六项测量

**原则一句话：能解释整个回路的才是根；只能解释对方指标的，是症状。** 而"下游变慢"与"我们重试多"**可以同时为真且互为因果**——方向不由哪句话更像来定，靠下面六项；其中 T5 是唯一决定性实验，T2／T3 是最便宜的两个破局点。

- **T1 相位（时间序，1s–10s 粒度）**：对齐 attempts、超时数、下游 handler p99、队列深度。retry 峰滞后于 latency 峰且幅度接近 1:1 ⇒ 真慢（重试是症状）；retry 峰领先或与 latency 共振荡、周期在秒级 ⇒ 回路。**5 分钟粒度会把环看成"同时发生"**，必须在秒级看相位。
- **T2 700ms 去哪儿（最便宜且最强）**：把端到端 900ms 拆成 DNS／TCP／TLS＋在途＋LB 排队＋accept 队列＋handler 执行＋回程。若 handler ≈ 200ms 而端到端 900ms，则 700ms 花在**排队与准入**——下游"自身负载没变"与"它确实变慢了"**并不矛盾，两句可同时为真**。再判一次：这 700ms 随 attempts 增长 ⇒ 放大器；与某个外部变量同步而与 attempts 无关 ⇒ 真外因。
- **T3 换分母（拆掉"我们没变"这句证词）**：问清下游"负载没变"量的是 QPS（完成数）、CPU，还是 in-flight／队列深度。Little's law `N = X·R`：并发上限被钉死时，R 涨、X 跌——**"QPS 没变"是饱和的指纹，而不是清白的证据**。要 concurrency、queue depth、per-client attempts、CPU steal。
- **T4 分群天然实验（零成本）**：按客户端版本／区域／实例分层看 retry 率。只有某一小群涨了 8 个点、其他群不动 ⇒ **不可能是"下游普适变慢"**（下游对所有客户端一视同仁），是那群客户端的本地条件（超时阈值／连接池／版本）。全群等比上升 ⇒ 外部共同因素权重上升。
- **T5 反事实 canary（唯一决定性，天级）**：1–5% 客户端关闭重试，或把重试预算压到 0 并加抖动。分钟级内下游 p99 回落接近 200ms 且业务成功率基本不变 ⇒ **方向反转已证实**，重试是主因；p99 不动 ⇒ 重试只是症状，回 T2／T3 找真外因。成本：一次配置变更 + 一次采样，**不必等任何人优化**。
- **T6 外生清单（找种子）**："机器没动、发布没有"≠"容量没变"。逐项核：客户端发布与超时／连接池配置、DNS／证书／keepalive、流量结构（新客户、新 region、批任务、扩缩容）、下游更深的依赖、缓存命中率、邻居噪声／宿主机迁移、限流阈值。

## L3 双根

**处置根（修本次，48 小时内可做）**：① 客户端：固定间隔重试 → 带抖动的指数退避 + 全局重试预算（如 ≤10% 唯一请求）+ 熔断；② 下游：按调用方的并发配额／隔离舱，让额外尝试在准入处被削平；③ 同步做 T5 canary——**先切断放大器，再用 canary 反向确认方向，两件事一次做掉**。

**消解根（灭这一类）**：把重试从"调用方的局部补救"变成"受全局预算约束的一等公民"，并把回路两端放进同一个可观测面。
- 不可发生判据：若当时同时具备 (a) 抖动退避 + 端到端重试预算（尝试放大有硬上限）(b) 下游按调用方的准入与并发隔离 (c) 观测区分 attempts/unique 与 queue/process —— 则"小幅扰动 → 4.5× p99 自持放大"这类问题**在结构上不可能发生**，同一扰动最多带来上限内的一次性抬升，不会自我维持。
- 可执行首边：在客户端加一个 retry budget 开关（一个计数器 + 一个开关，天级）+ 把 p99 拆成 queue／process 两段上报（小时级）。
- 成本量级：天级人力、配置级改动，不需要换环境。（量级核定交 📐 公式图。）

## L4 迁移出口

若消解根最终落到"把回路交给一个所有者"（服务网格 sidecar 统一下沉重试策略 / adaptive concurrency limit / 客户端负载均衡）：
1. **重试语义归属**：sidecar 重试与应用重试并存 = 双层放大，必须只在一层重试（迁移中最容易新增的事故）。
2. **幂等与重复副作用**：削掉重试后，原先被掩盖的错误暴露给业务，需要幂等键与补偿链路。
3. **预算参数标定**：retry budget 阈值、并发上限需要 SLO 与流量模型，不能拍脑袋。
4. **可观测性改造**：attempts/unique、queue/process、per-client 公平性指标必须落盘，否则回路依旧无人看见。
5. **组织能力**：谁拥有跨团队的重试预算与准入策略、谁对"回路"这一层 SLO 负责——这是权责重划，属 org-process。
→ **本次问题降级为第 4 项 + 第 5 项的一个子项**：不是"下游慢"，而是"回路无主"。

| 个例根⑥② 分母／定义域伪影，排队与处理未拆开 | 共因 | 改指标 | 一次取数 | T3 |

## 结论

1. **方向**：不要先接受"下游变慢 → 所以我们多重试"这个单向叙事，也不要急着反过来说"我们多重试 → 所以下游变慢"。两句都可能为真，因为它们是**同一个回路的两侧**。判定方向只靠三件事：**700ms 花在谁的账上（T2）、下游"负载没变"用的是哪个分母（T3）、关掉重试后它掉不掉（T5）**。三条都是天级成本，做完再决定这张工单还要不要往下压。
2. **根源（类根）**：不是下游慢了，也不是我们多按了几次重试——是**重试被当成调用方的局部补救，去消耗一个共享且有限的准入资源，而这条闭合回路没有任何一方拥有**。缺的就是三样：有抖动且有全局预算的重试；下游按调用方的并发准入；能把 attempts/unique 与 queue/process 分开的观测。这三样缺位时，任何一周的小扰动都会长成一次"下游 p99 涨 4.5 倍"，而双方都能拿出自洽数据证明自己无辜。
3. **可以马上说给下游的一句话**：请给 concurrency、queue depth 与 per-client attempts——**"QPS 没变"在并发被钉死时正是饱和的指纹**（`N = X·R`，R 涨则 X 跌）。

**✅ 验证**：无实测数据。本题为推理题且题面禁止取证（不得搜索或读取本机文件复现），故所有判定以"待测项 + 该测项的判定阈"给出，未编造任何测量值。

**⚠️ 异常／矛盾／空白**：
- ⚠️ **量级空白**：「+8% 负载 → 4.5× p99」的定量链路本轮未算（属 📐 公式图），因此"尾部集中到 2–3 倍"只是可行性论证，不是结论数值。
- ⚠️ **类别未完全排除**：网络与组织流程两支无数据可排除，已挂起而非删除；若最终根落在其中一支，本图 L2 骨架仍成立（回路位置变了，结构没变），但 L3 消解根需重写。
- ⚠️ **题面自身有倒推风险**：团队结论把相关性直接赋了方向，并把验证责任外包成工单——下游无法证明"我没变"，这是不可证伪的指控结构。建议把"换证据互相指控"改成 T5 的交互式测量。另：3% 的重试率基线本身说明系统长期就在膝点附近运行，本类问题不是这次才出现的，只是这次扰动大了一点。
