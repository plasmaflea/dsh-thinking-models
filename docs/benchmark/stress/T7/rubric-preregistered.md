# T7 预注册口径 · 因果方向反转

写定时间：发题之前。跑完后不许改判定式。

## 题面（逐字，五份必须完全一致）

> 我们的客户端重试率从 3% 涨到 11%，同一周下游服务的 p99 从 200ms 涨到 900ms。团队结论是「下游变慢，所以我们才多重试」，已经给下游发了工单要求优化。下游回说：他们自身负载没变、机器没动、发布也没有。你怎么判断方向？根源在哪？

## 埋设

真根：我方先动——客户端超时从 2s 收紧到 800ms（并发上限同时从 4 提到 8）。于是我方制造了重试，重试放大下游负载，下游 p99 才上升。**题面里"下游变慢导致我们重试"的因果是反的。**

## 关键词表（机械计数，不采信自述）

| id | 判定项 | 正则 |
|---|---|---|
| K1 | 提出方向判别实验 | `关闭重试|关掉重试|停掉重试|放回 2s|恢复到 2s|反向实验|对照实验|先停用重试` |
| K2 | 识别重试为负载放大器/正反馈 | `正反馈|放大器|放大效应|雪崩|重试风暴|thundering|自我强化|自我放大` |

| K4 | 要求分位/分布而非均值 | `分位|p99|p95|直方图|分布|均值` |

## 判定规则（预注册，四条）

1. **主判定**：单份同时命中 K1 且 K3 ⇒ 记为「判对方向」。
2. 若 **≥4/5** 判对方向 ⇒ 本题不构成压力，写「饱和」。
3. 若 **≤1/5** ⇒ 本题成立，并记「模型倾向于接受题面给的因果」。
4. 只报各 K 的命中份数与中位篇幅，**不报答对率**（真根只有一份，判据在 K1∧K3 已经机械化了）。
