## 三、四条结论

### 1. 我的"埋设真根"系统性偏浅——出题人的答案不是天花板

- **T7**：我埋「因果方向反了（我方超时收紧导致重试风暴）」。五份**都没有**直接认这个答案，而是判「r 与 p99 都是延迟分布的导出量，两个方向在聚合曲线上等价，**现有信息下不可判定**」，并各自给出干预实验（retry-off 分片 / single-attempt 探针 / 10% canary 撤压）。这比我的埋设更严谨。
- **T8**：我埋「limit 按 P50 设」。K2 命中 **0/5**——五份全部改写成更根本的一层：**OOMKilled 以 cgroup 记账量为判据，而人的观测是进程 RSS × 时间平均，两者不是同一计量域**（`记账/口径` 词频 48–98 次/份，`tmpfs/shmem` 15–35 次，`节点级 OOM` 14–20 次）。"查不到凶手 + 曲线平"不是证据缺失，是观测面与记账面错位。

### 2. 真正的短板不是"不会认输"，而是"数据量的错觉"

T7 与 T3 是同一能力的对照组：

| | 题面形态 | 认输表现 |
|---|---|---|
| T7 | 题面**自带矛盾**（双方都称无变化） | **5/5** 判「不可判定，须做干预实验」 |
| T3 | 数据**看起来完备**（六维指标齐全） | **0/5** 判「不可辨识」，全都硬定案 |

⇒ S2（承认不可辨识）不是能力缺失，而是**被数据量的丰满度抑制**：指标越齐，越倾向于把「可分解」当成「可辨识」。这条比"模型不会认输"精确得多，可以直接写进论文的失败模式。

### 3. 树外行为守规：知识树覆盖不到时不会硬套

T10 故意落在 `org-process`（树里只是"待建候选"，无节点文件）。五份**全部**显式登记树外分支并写 v2 候选（K1 5/5），全部用「需求必经流程」生成轴而不是列举（K2 5/5），类根一致落到「准入权与产能成本分离 / 无人持有拒绝权」（K3 5/5）。**没有一份拿 `software` 的六子层去量化组织问题**——这是 v4 知识树机制最正面的一次证据。

### 4. 规则 13（交付前负边审计）在真实生效

20 份里 3 份主动加载倒推图审计题面自带的结论（T7 团队结论、T10 的"培训无效"），其中 T7-a 明确指出团队「用发工单处理了反例」命中走形 #3。这不是我要求的，是 `AGENTS.md` 规则 13 被独立执行。

## 四、本轮暴露的三处口径缺陷（我的问题，不是 agent 的）

1. **K1 词表漏检**：T7 的 K1 机械计数 3/5，人工复核 5/5——b 写「retry-off 分片 + single-attempt 探针」、c 写「canary 撤压」，都不在正则里。
2. **K4 是"提及"计数而不是"主张"判定**：T9 的「重写」出现 4–13 次，多数是在说「**不是**重写」，机械计数无法区分主张与否定。
3. **预设真根只能测"我想到的答案"**：T8 的 K2 0/5 是**假阴性**——不是它答偏，是它答得更根本。凡"我的埋设"被更深的机制覆盖，机械判分就会误判为失败。

⇒ 方法论结论：**纯文本题的机械判分只对"是否违规/是否守规"有效，对"是否更好"无效**。要测"更好"，必须回到注入真值 + 可执行环境（G 系列）。
