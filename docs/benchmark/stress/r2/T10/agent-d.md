## L2 逐层回溯

### 层1　轴（生成源：恒等式 · 队列守恒）

生成理由：任何需求池的存量变化只有四个来源，无第五项，四格由等式机械生成，不靠联想列举：

> **backlog(t+1) = backlog(t) + 流入(t) − 完成(t) + 回流(t)**

| 格 | 该格在管什么 | 该格故障时的可观测症状 |
|---|---|---|
| A 流入 | 需求以什么速率、经谁的手进入池子 | 池子件数每季度增长；需求来源多头且各自都认为自己是「必须的」；没有任何一条需求被挡在门外过 |
| B 完成（有效产能） | 单位时间真正交付的数量 | 12 人名义产能近乎恒定，但同时在手 5~10 件，切换损耗使有效产能显著低于名义产能；越忙越慢 |
| C 回流 | 已完成的东西被变更/重开/返工后二次入队 | 「已完成」的需求被重新打开；变更不重新走准入，直接插回队列 |
| D 存量治理 | 排序、砍需求、清队列 | 每季度都砍、砍完下季度照样满；砍掉的都在队列中尾部，前部没动过；排序结果每周都在变但池子长度不变 |

三判据检验：**正交**——A 格根（无闸门）不解释 B 格症状（切换损耗），B 格根（WIP 无上限）不解释 C 格（变更不入队）；**可生成**——由守恒等式直接切出；**可观测**——每格有专属症状（上表右列）。**全空列检验**：四格均有症状，无空格 ⇒ 轴成立，不需要换轴重切。

### 层2　哪一格在驱动（因果分层）

关系语法（只允许两种边，逐条标必要/充分）：

- 流入(t) > 完成(t) → backlog 单调增长：【**充分条件**】（只要速率不等式成立，增长必然发生，与排序无关）
- 拒绝权缺位 → 流入无闸门：【**必要条件**】（不分配「说不」的权力，就不可能有有效的限流）
- 在途并行件数↑ → 有效产能↓：【**充分条件**】（切换损耗）
- 例外直插 → 准入闸门失效：【**充分条件**】
- 「优先级培训」→ backlog 长度：【**⊥ 无关边**】（只作用于顺序，不作用于长度）

关键结构判断：**在恒等式里，D 不是自变量，是等式左边。** 排序与砍需求作用在「顺序」和「存量」上，对「流入速率」和「产能」没有任何系数。所以：

- 过去两次干预（优先级培训、季度砍需求）**全部落在 D 格**；
- 而失衡由 A / B / C 驱动；
- ⇒ 干预全部作用在系统的**输出项**，而失衡在**输入端与产能端**。这不是执行力问题，是作用点选错。这就是「砍了又爆」「培训了也没用」能被机械推导出来的原因。

### 层3　为什么 A 无闸门、D 无实效 → 权力位置空缺

「拒绝」不是一个态度，是一项**需要被授予的权力**。当前结构里：

- 流入侧：请求方（上级、销售、客户、兄弟部门、团队自己）**人人有权加**，且各有正当业务理由；
- 流出侧：12 人各自对接各自的需求方，**没有任何人对全公司的需求来源拥有否决权**，也没有人有权对外声明「本季度只做 N 件」；
- 中间层：于是「排序」成了唯一可执行的决策形式，而**排序在超载系统里是零和的**——换顺序不减少任何一条需求。

两层干预的失效因此可精确归因：
- **优先级培训**：提升了「确定顺序」的能力，而系统缺的是排序的上游（容量边界）与下游（拒绝权）。相当于在一条没有闸门的水池里教人怎么更科学地舀水。
- **每季度砍需求**：一次性「清淤」，改的是存量（等式左边），不改速率；且砍掉的集中在队列中尾部，真正驱动超载的前部（已承诺 / 已直插）没动。**砍完那一刻速率失衡原样保留 ⇒ 回弹有确定的时间常数（约一个季度），必然复现。**

> **类根（面对整个大类）：**「谁能说不」这个**权力位置在结构上是空缺的**——流入侧人人有权加，流出侧无人有权拒，而中间的「排序」被误当成了「决策」。
>
> └ **个例根（本次的具体机制）：**两次优先级培训只提高了确定顺序的能力；季度砍需求只做了一次性清淤（改存量不改速率）。两者都不触碰流入速率与容量承诺，因此下季度回弹是**可预测的结构必然**，不是团队执行力或认知水平的问题。

- **背景现象**：12 人、需求永远排不完、每季度砍、砍完照爆、两次优先级培训无效。

## L3 双根

**处置根（修本次）：把「砍需求」从一次性清队列，改成每季度一次的「容量核定 + 准入封顶」。**
先算可承诺容量，再倒推可承接件数，再只准入这个数：
本季度可承诺人时 ≈ 12 人 × 13 周 × 40 h ≈ 6240 名义人时；扣除运维/支持/休假/会议 25%~30% ⇒ **约 4400~4700 可承诺人时**。用上一季度的「单件平均实际耗时」去除，得本季度可承接件数 N。只准入 N 件，其余进「不承诺池」（明确无时间承诺，不是 backlog），并写明超出部分的排队与例外规则。

**消解根（灭这一类）：在组织里显式设立并公开行使一个「承诺权位置」**——对需求流入有否决权、对交付时间有承诺权、对例外有记账权，且该位置对上唯一、对下分发。

1. **不可发生判据**：若当时该位置存在且被行使，则流入速率被容量上限约束 ⇒ backlog **不可能**单调增长；排序在容量之内是廉价操作 ⇒ 「培训无效」这一现象也不会出现。本类问题在结构上不可能发生，不只是变少见。
2. **可执行首边**（从现状出发的第一步，可以很小）：**本周发布一张《本季度容量公告》**——写清可承接件数上限、准入标准、超出部分的排队与例外规则，由团队负责人签字并对全部需求方发出。不改组织架构、不增编制、不需要先有数据系统。
3. **成本量级**：发起成本 < 1 人日（一次工时核算 + 一份公告 + 一次向上沟通）。真正的成本是**组织成本**：需要一次向上授权——**无背书则公告退化为纸面，这是本消解根唯一的失败模式**。定量（工时折算、N 的取值、例外比例）登记挂起交 📐 公式图。

## L4 迁移出口

消解根指向的是结构变更，故本次问题必须降级为下列清单中的一项：

1. **单点风险**：承诺权集中 ⇒ 成为政治靶子与瓶颈。缓解：容量公式与准入标准公开、例外逐条记账、按季度复核。
2. **绕行**：被拒的请求方会走「更高层直插」。缓解：上级背书 + 例外通道显式化（例外占用下季度容量，必须记账）。
3. **培训被降级**：优先级培训从「解决方案」降为「必要组件」（容量之内仍需排序），需重新定位并保留。
4. **可观测性缺口**：闸门开合无据 ⇒ 需四个速率指标（流入/完成/在途/回流），每季度一次即可。
5. **合同级需求冲突**：销售/客户合同级需求天然优先，若不作显式输入，闸门会被合同绕过而失效。
6. **关系成本**：执行「拒」的人需要话术与授权文件，这是团队负责人的真实人际成本，不是技术活。

→ **本次问题降级为第 2) + 第 5) 项的联合子项**：「例外通道怎么设计，才能既不被绕过、又不让合同级需求把闸门卡死」。

## 结论

问题不在「不会排序」，而在**没有任何人被授予说「不」的权力**：流入侧人人可加，流出侧无人可拒，中间的排序被误当成决策。因此每季度的砍需求只是一次性清淤（改存量不改速率），两次优先级培训只是提高了排序质量（改顺序不改长度），回弹是可预测的结构必然。要灭这一类，先做一件小事：算清本季度可承诺容量，发一张《本季度容量公告》，把超出容量的需求明确挡在「不承诺池」外面——并拿到上级背书，因为这张纸没有背书就是纸。
