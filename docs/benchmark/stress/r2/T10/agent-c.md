L2 逐层回溯

轴生成（生成式，非列举）：主轴 = **必经时序**——一条需求从出现在组织里到离开团队，必然经过五个位置，一格不缺（不进入就无从承诺；不承诺就不会被做；不做完不会释放；不释放就没有数据）。副校验 = 恒等式 **L = λ × W**（队列长度 = 到达率 × 周期时间），用于检查「培训」这一干预落在等式的哪一项。

| 格 | 该位置在管什么 | 该格故障的可观测症状 | 判定 |
|---|---|---|---|
| 1 入口 intake | 需求如何进入组织视野、谁有权登记 | 同一需求有三个版本/被不同来源重复提出；季度末「砍需求」时找不到完整清单，只能说「大概这些」 | 无唯一登记点 → 总量不可知，「砍」失去对象 |
| 2 准入承诺 commitment | 谁能把需求变成对外承诺、依据什么定 | 承诺量按「想要」而非按实测吞吐定；发出承诺的人不在执行队列里；团队第一次看到承诺日期 | 承诺权与容量实测分离 |
| 3 在制执行 WIP | 同时在手多少件、谁定顺序 | 每人同时 3–5 项，任何一项都「快完成了」，切换成本高，无在制上限，插队无需挤掉任何东西 | 队列可无成本增长 → 只有排序，没有准入 |
| 4 交付释放 release | 完成是否真的离开队列 | 验收拖延、完成即追加需求、返工率高；队列只进不出，「做完的」不减少「要做的」 | 释放门打开，负反馈缺失 |
| 5 反馈度量 feedback | 系统能否自我纠正 | 无法回答「上季度砍掉的那批需求现在在哪」；培训效果无法度量，只能用「感觉更清楚优先级了」评价 | 无闭环 → 同一环每季度重跑 |

三判据自检：**正交**——五格症状互不解释（入口的症状是「清单不存在」，承诺的症状是「日期与容量脱钩」，在制的症状是「切换成本」，释放的症状是「做完不减少」，反馈的症状是「无法回溯」）；**可生成**——时序必然，缺任一格需求都无法完成一次完整流转；**可观测**——每格都有专属且可当场取证的症状。**无空格**，故不触发「全空列 ⇒ 换轴」。

→ **类根**：**这个系统里不存在「拒绝」这个动作的执行位置——决策权（决定什么进来、什么被对外承诺）与成本承担（做不完的加班、质量、离职）被安放在不同的人身上，而两者之间没有任何零和约束把它们绑回一起。**
　　　└ **个例根**：12 人团队的季度循环 = 季度初由非执行者按「想要」承诺 > 实测量 → 在制在第 2–3 周触顶 → 季度末以赶工＋欠债收尾 → 下季度用「上季度欠的 + 插队」重启。培训在这一环甚至**加剧**：它把「谁更急」的判断做得更快，等于提高了对所有插队的受理速度，而队列上限一格没动。

恒等式校验（解释「两次培训为什么必然无效」）：L = λ × W。培训改的是第 3 格里「单件工作的排序质量」——它只是在既定总量内做**分配**，不改 λ，也基本不改 W 的均值；而 λ 由「谁在什么约束下对外承诺」决定，这件事发生在团队之外。**干预变量（判断质量）与故障变量（λ 的控制权）不是同一个**——这是结构决定，不是培训执行不力。

L3 双根

**处置根（修本次）**：本季度只交一件可交付物——一张**「本季度不做清单」**，且这次「砍」的对象必须是**已承诺、已排入但尚未开工**的项目，而不是「优先级本来就低的候选池」。判据：只有在已承诺区做减法，队列长度才会真正下降；在候选池做减法只是重排期望。

**消解根（灭这一类）**：**把「承诺」变成一个必须消耗容量的动作——单一入口 + 承诺数不超过实测吞吐 + 每一次进入必须写明「挤掉了谁」。**
- ① 不可发生判据：若采用，任何需求进入都必须在算术上挤掉一个已存在项 ⇒「队列无限增长」在结构上**不可能**，而不只是变少见；「砍需求」从一件需要勇气的判断，降级为一次必须填完的空格。
- ② 可执行首边：**本周建一张唯一登记表，表上有一列「本次挤掉了谁」；填不出挤占项的请求不进队列。** 不需要组织重组、不需要新系统、不需要预算。
- ③ 成本量级：一次性搭建 **~1 人周量级**、运行 **团队工时的低个位数百分比量级**；真正的成本在**政治项**——必须有一位被正式授予「说不」权力并承担其后果的角色，这一项是本方案唯一可能失败的闸门。量级的精确值须交 📐 公式图核定，本图不凭空给数。

L4 迁移出口（消解根指向「把承诺与容量绑定」，必然带来的新问题清单）
1. **拒绝权的归属**：谁说不、对谁负责、其绩效怎么算（组织能力）。
2. **需求来源方分流**：销售／客户／老板各自要有替代承诺出口，否则绕过单一入口。
3. **度量基础设施**：吞吐、周期时间、在制数的实测——没有分母，「不超过吞吐」无法执行。
4. **紧急通道协议**：真实 P0 的插队规则；没有它，单一入口在第一周就会被合法绕过，系统回到原状。
5. **存量债排程**：本季度欠下的技术债与质量债必须显式进队列，否则它们变成隐形的 λ。
→ **本次问题降级为第 3 项（度量基础设施）与第 4 项（紧急通道协议）的联调子项**：它不再是「需求管理问题」，而是「承诺—容量绑定系统」的第一版实现。

结论（三句话）
1. 根源不在排序能力，而在「拒绝」这个动作在整个系统里**没有执行位置**：决定进什么的人不承担做不完的成本，承担成本的人没有权拒绝，两者之间没有零和约束把责任绑回去。
2. 因此「砍需求」每季度只能是一句口号——它现在是一次可选的判断，而一个可持续的系统需要一个**数学上必须发生**的动作：进一个，就必须挤掉一个。
3. 培训无效是结构决定的：它调的是判断质量，故障变量是 λ 的控制权；而且它顺带把插队响应变快了，是负向的。
