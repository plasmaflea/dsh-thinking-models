**类别**：分布式系统的**容量-时延反馈环（正反馈／元稳态）× 归因口径不可对账**。

## L2 逐层回溯

### 选轴（生成式，不列举）
两条生成源切两张正交的轴：
- **轴 A（必经时序）**：一次逻辑调用必然经过 —— 客户端判定 → 传输 → 下游入口排队 → 下游服务 → 重试反馈 → 观测归因。六格按先后必然存在；可省则省、**不可漏格**。
- **轴 B（恒等式）**：环增益 `G = (∂attempts/∂latency) × (∂latency/∂load)`。`G ≥ 1 ⇒ 自激（元稳态双稳）；G < 1 ⇒ 任何外生扰动都被阻尼`。这条恒等式直接决定了"谁先慢"在数学上不可判——环里没有起点。

### 层1：轴 A 逐格（每格附专属症状）

| 格 | 该格在管什么 | 该格故障的**专属**症状 |
|---|---|---|
| A1 客户端判定与发起 | 超时阈值 T、重试策略、并发/连接池、DNS 缓存 | 重试率阶跃而 p99 涨幅不成比例；T 落在分布陡峭段时有"悬崖"效应 |
| A2 传输 | RTT、连接建立/TLS、丢包重传、conntrack/NAT | RTT 中位数同步恶化；**连接速率↑而应用 QPS 平**（重试触发重连，负载藏在握手与 fd 上） |
| A3 下游入口排队 | accept 队列、线程池/信号量、限流器 | **goodput 平台 + in-flight↑**：completed QPS 平、时延涨 |
| A4 下游服务 | 容量 ρ、服务时间、GC/锁/慢依赖、工作放大 | 服务时间上升（**无排队也变慢**）＝真外生；服务时间平而等待涨＝排队 |
| A5 重试反馈 | 重试预算、抖动、可取消性/截止时间传播 | 无预算＋无抖动＋超时不取消 ⇒ 每次重试把**完整工作再复制一份**，且复制集中在最慢那部分 |
| A6 观测与归因 | 口径（attempt vs completed；客户端 p99 vs 服务端 p99）、粒度（周 vs 分钟） | 两端口径不可对账；周级聚合把因果顺序（定序）抹平 ⇒ 方向不可判 |

### 层2：判定哪些格非空

- **A4 非空但方向未定**：题面的 200→900ms 若是**端到端（我方观测）**，它 = A2+A3+A4+A1 排队之和，不能直接命名为"下游变慢"；若下游报的是**服务端服务时间**，则 A4 明确非空（外生），但对方"负载未变"意味着他们的 ρ 不会被我们推高——**两句话可以同时为真**，缺的正是**分解**。
- **A3 高度可疑，且是唯一能同时解释"他们说负载没变"和"我们看到更慢"的格**：完成吞吐（goodput）饱和时，多出来的重试只变成**队列深度与排队时延**，不会变成更多的完成请求。所以他们的 QPS **真的可以"没变"**。
- **A5 确定非空**：11% 的重试＋无预算＋无抖动＋超时不取消 ⇒ 环增益被抬到 1 附近甚至以上。
- **A6 确定非空**：周级两个聚合数无法定序；两端指标不同源。

**全空列自检**：不存在全空格（A5/A6 必非空）⇒ 坐标系有效，不需要换轴重切。

### 量级括号（这是"200→900 能不能被重试单独解释"的关键）

用 M/M/1 的尾部时延 `t99 = S·ln(100ρ)/(1-ρ)` 做括号（**理想化：单服务台、泊松到达；真实是多服务台/连接池，曲线会被推迟，但 ρ→1 的发散性不变。所以下面的倍数只用来"读 ρ 落在哪一段"，不是精确值**）：

| 下游基线利用率 ρ₀ | 仅 +9% offered load（= attempts 从 1.03 涨到 1.12）后的 t99 倍数 |
|---|---|
| 0.70 | 1.3× |
| 0.80 | 1.6× |
| 0.85 | 2.1× |
| 0.90 | 5.4× |

**读法**：观测到的 4.5×（200→900ms）恰好落在 **ρ₀ ≈ 0.87–0.90** 的括号里。也就是说——**若下游已经饱和到这个程度，"重试把工作完整复制一份"这一条通道就足以解释全部 4.5×，不需要任何外生变慢**；反过来若 ρ₀ ≲ 0.7，同一条通道最多 1.3×，剩下 3.4× 必须另有来源（此时 H1 转正）。**ρ 就是那个判别数。**

### 类根（两个根，各有其位）

**类根 ①（结构类根）**：系统里存在一条**增益可以 ≥1 的正反馈环，而环上没有任何装置把增益压回 <1** —— 重试（可放大）× 接近饱和的利用率（可放大）× 无预算/无抖动/不可取消（放大方向全开）。在这个结构里，"谁先慢"是循环定义：任选环上一点切一刀，都能把另一侧指为原因。**团队找到的不是根，是切环的位置**，而他们恰好切在自己不负责任的那一段。
└ **个例根**：本周某个**可以很小**的扰动（超时阈值被调、客户端/重试库版本、连接池大小、DNS/LB 权重、某实例或分片抖动、某批量任务、下游某个二级依赖的 GC）把环从阻尼区推进到自激区；此后 3%→11% 与 200→900ms 是**同一条环的两个读数**，互相喂养成一个新的稳定点（元稳态）。扰动幅度不重要，**放大的是环**——这就是为什么"下游什么都没动"与"延迟涨 4.5×"可以同时为真。

**类根 ②（认知类根）**：两侧都只有**结果级、聚合级、口径不同源**的指标（我方按调用、对方按完成；p99 一个端到端、一个服务端；周级窗口），缺 attempt 级账本与队列级指标。于是"哪一侧先变"**在数据上不可判定**——争论不是判断力问题，是**账本缺失**。
└ **个例根**：本次归因走了"谁的现象更显眼"，而不是"谁的账本更细"，结论落到了不可证伪的一侧。

## L3 双根

### 处置根（修本次；按代价升序，全部我方单方面可执行）

1. **口径与变更对账（分钟级，先做，可能直接归零）**：重试率的分子分母／埋点／SDK 版本／聚合窗口这周有没有 diff；我方超时、连接池、重试库、DNS/LB、依赖版本的变更清单。3.67×（3%→11%）的阶跃里，"口径改名"是有相当先验的解释（例如分母从"已成功请求"改成"全部尝试"，或重试计数从 A SDK 迁到 B SDK）。
2. **剂量-反应（一次查询，用已有数据，不需要新埋点）**：按下游 interface／分片／租户分组，看时延涨幅是否与该组"重试暴露度"成比例；**特别看从不被重试的只读接口**——等幅恶化 ⇒ 外生；只落在被重试的调用上 ⇒ 内生。
3. **索取单点判别数（一封工单，但改掉原工单的措辞）**：过去 8 周按分钟的 `completed QPS / in-flight 或队列深度 / 利用率 ρ / accept 级连接与请求计数 / 重复请求计数`，并确认 p99 是**服务端服务时间**还是**端到端**。原工单问的是"你们为什么变慢"（不可答），新工单问的是"给我这五个数"（可答）。
4. **干预实验（1 人日，最具决定性）**：把重试策略换成 **retry budget**（重试量 ≤ 成功量×β，β≈10%）＋ **full jitter** ＋ 传 **deadline/取消**，先 1% 流量灰度 30 分钟。**p99 回落 ⇒ 环被证实且已止血；p99 不回 ⇒ H1 转正，工单才成立。** 这是唯一能把"方向"从争论变成观测的动作，且爆炸半径可控。

> 关键判断：**即使下游真的变慢了，处置也必须先落在我方的环增益上**——你控制不了对方的服务时间，但环增益是放大器，而放大器在你手里。

### 消解根（灭这一类）

**把"重试"从"每次失败的自由动作"改为"有全局预算的受限资源"，并让时延归因变成同一本账的读数，而不是跨团队推断。**

- **不可发生判据**：在 `retry budget + jitter + deadline 传播/取消 + attempt 级账本` 下，本类问题在**结构上**不可能发生 ——
 (a) 重试总量被硬钳制在成功量的 β 倍，环增益 `G ≤ β·(∂L/∂load)` **有界恒定**，扰动无法自激，双稳态里的"慢平衡点"被删除；
 (b) 任一时延上升都能在同一张账本上分解为 `setup / queue / service`，"谁先慢"不再需要跨团队协商。
 这不是"让它变少见"：它删掉的是"重试可以无限放大"和"归因靠推测"这两条**通路**本身。
- **可执行首边**：客户端 SDK/中间件换重试策略（一个配置项＋一个退避中间件），即处置根 4；账本侧先在**我方出口**埋 attempt/duplicate 计数，不必等对方配合。
- **成本量级**（量级，交 📐 公式图定量）：策略改造 ≈1 人日；灰度 1 天；自有侧账本 ≈1 人·周；跨服务账本对齐 ≈数人·周。相对"每周一次 4.5× 尾部雪崩"的代价，低一个数量级。β 的取值由 SLO 与 p99 的关系定：`β ≈ 可接受的额外时延放大余量 ÷ 尾部请求的单位工作倍数`，需代入实测的 S、T、ρ。

## L4 迁移出口

消解根指向"重试变成受限资源 + 账本化"，会引出下面这批新问题，**本次问题降级为其中一项**：
1. **数据与语义**：预算拒绝重试时对上游的呈现（快速失败／排队／降级返回）；幂等边界；重复写是否已经发生（重试=重复写，风险与重试率同阶）。
2. **运行与自启（此处为运行姿态）**：β 的归属（谁定、谁能改）；熔断恢复的探测策略；跨服务 deadline 要求下游支持取消，否则退化为纯预算约束。
3. **可观测性**：账本的数据量与采样；告警从"p99 超标"改为"重试预算耗尽率 + in-flight/ρ"。
4. **凭据与权限**：无（本例不涉及）。
5. **组织能力**：谁拥有"全局重试预算"这个跨团队参数；工单文化从"请优化"改为"请交换账本"。

→ **本次问题降级为**：第 2 项中的「**β 取值与灰度验证**」——"这次为什么慢"变成"预算参数该设多少"的一个子问题。

## 结论（三句话收敛）

1. **方向不能靠箭头判，只能靠"能杀掉其中一支的观测"判**：先对账口径与自身变更（分钟级，可能直接归零）→ 用已有数据做剂量-反应 → 向对方要**一个数**（ρ / 队列深度 / goodput）→ 最后一招是 1% 流量关重试的干预实验。这是唯一能把方向变成观测的动作序列。
2. **根源不是任何一个组件，而是一条没有限幅的正反馈环**：重试（无预算、无抖动、不可取消 ⇒ 工作被完整复制）× 接近饱和的利用率（ρ→1 时尾时延发散 ⇒ 200→900ms 只需 +9% 的重复工作，在 ρ₀≈0.87–0.90 即被完全解释）。所以"下游什么都没动"与"延迟涨 4.5×"**可以同时为真**；团队把环上的一侧误当成了起点。
3. **消解根是给重试装上预算与账本**（budget + jitter + deadline + attempt 级账本）：它让这一类在结构上无法发生——放大通路被钳制，归因不再需要协商。该发的工单不是"请优化"，而是"请交换 ρ、in-flight、accept 级计数与 p99 口径"。

[⚠️ 异常/矛盾/空白]
- 题面缺 4 个关键事实：① 200→900ms 是端到端还是服务端服务时间；② 下游的利用率/队列深度；③ 重试率的口径与这周是否改过；④ **我方**一周内的变更清单。"下游没发布"被当成"下游没变"，是把"发布"当成了唯一变更源——配置、流量形态、二级依赖、机器降频都改得了它。
- "同一周"是弱证据：周级聚合在数据上已经决定了"方向"不可判，需要分钟级 join。
- 若 11% 已含二次重试而分母是"请求数"，实际 attempt 放大是 `1/(1-p)`（1.03→1.12，即 +9%）；这个数**只有在 ρ 已知时才能定"够不够解释 4.5×"**。把 11% 直接读成"+11% 负载"会系统性低估尾部效应。

[💡 灵感备注]
- 这类"两个团队各说各话"的争论，判据不在技术，而在**谁的账本更细**。可复用判据：任何跨团队归因争论，先问"能不能把这个数分解到不再需要协商"；分解不了，就先去建账本，不要先发工单。
- 超时阈值 T 是这个系统里最便宜的"环增益旋钮"：T 落在时延分布的陡峭段（p95–p99）时，一次极小的分布平移就能把重试率翻几倍（灵敏度 = 生存函数在 T 处的 hazard）。调 T 比扩容量便宜两个数量级。
