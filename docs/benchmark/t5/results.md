## 一句话结论

**技能不改变结论方向，只改变产物的记账方式**：两组都把「v3.4 串行化」定为主因、把 CDN 定为放大器/混淆变量，也都用了同一个算术指纹 `1−(1−p)² ≈ 2p`；差别在体量（2.4×）、表格密度（4.6×）、排除项公开程度（3 → 16 条）、以及「声明不可辨识」的比例（1/5 → 3/5，**未达预注册的 4/5 阈值**）。

## 按预注册规则判定

1. **M1（声明不可辨识）**：A 1/5、B 3/5。既不是「两组都 5/5 或都 0/5」（无差异），也没到「仅 B 组 ≥4/5」（技能有效）。⇒ **方向为正，证据不足**。n=5 下 1/5 vs 3/5 在二项检验里不显著，不写成"技能让它更诚实"。
2. **M2（排除项条数）**：A 中位 3、B 中位 16，**区间不重叠**（A 最大 3 < B 最小 6）。这是本轮唯一无歧义的差异。
3. **M3（带判据的下一步）**：两组都 5/5 ⇒ **无区分力**，该指标作废。
4. **不设答对率**：本题真根在信息上不可确定，两组都只是在给定信息下做最大似然推断，任何"答对"判定都是作者主观。

## 五条值得记下的发现

1. **方法内核不是技能给的**：A 组五份**全都**自己推出了 `1−(1−p)²≈2p` 的串行指纹、`F−R=1.0%→2.0%` 的拆解、Little's law 与 ρ/(1−ρ) 的非线性放大、以及「风控规则没动≠拒绝没变」。这些在 T5 之前被判为「技能的作用」，本轮证伪——它们是模型先验，与技能无关。
2. **技能改的是"记账"不是"推理"**：B 组多出来的约 5750 字符、25 行表格，主体是挂起表（每条带恢复条件）、候选根排序（Share×Lever÷Cost）、L0–L4 分层。A 组把同样的排除过程写在散文里（「顺便排除了…」）或干脆不写。
3. **两组在"最该说不可辨识"的地方都不够坦白**：题面明说无原始日志、四变更同期，A 组只有 b 一份、B 组三份明确写了信息上不可判定。**技能的挂起表并没有转化成"认输"**——它把不确定性格式化了，但没有提高承认不确定的概率（3/5 vs 1/5，不显著）。
4. **B 组内部反而更发散**：A 组五份结论高度同质（都指 v3.4）；B 组出现「CDN 身份保真度导致风控误拒」（e）、「时延预算是无主公共资源」（d）、「α×β 双因叠加」（c）等不同骨架。**技能带来的是结构化多样性，不是更高的共识**。
5. **两组的自证陷阱识别一致**：都指出 CDN 厂商的「无异常」口径不含客户端端到端与回源 RTT，也都指出「只加了一个查询」在阈值附近是乘性伤害。

## 已知混杂（不许拿这份报告做因果主张）

- B 组多出的**不只是技能**：还有 `AGENTS.md` 的常驻纪律（模式标记、挂起表必填、五层骨架）。差异不能单独归因于「技能」。
- **作者非盲**：我已知 T3 结果、题面构造与评测口径。
- 子会话共享同一宿主、同一模型版本；n=5 极小。
- 「裸机」并不真空：剩余 5 个内置技能（office-×3、diagnose-windows-sandbox-acl、hindsight-coding-agent）关不掉，但它们与本题无关。
