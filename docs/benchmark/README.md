# before / after 对照：结构化技能是否改变输出

## 这是什么

同一批问题，问两次：一次给**装了技能与工作区约定的宿主**（after），一次给**把技能和约定都撤掉的宿主**（before），两份原文并排，用**跑之前就定死的指标**数差异。

不是排行榜。每条件 n=1，单次运行，目标是**证明差异存在且可被计数**，不是"平均提升 X%"。

题面的**逐字定稿**在 [prompts-v2.md](prompts-v2.md)，本页只放摘要与结果。

**三个读数**

1. **机制生效**：轴从"列举分支"变成"由必经时序生成"；每条挂起都能被推翻（恢复条件非空）；候选根按可验证性排序。⑦ SxS／清单**补回来了**——v2 漏、v3 命中。
2. **⑧ 受限令牌／低完整性仍然漏**。原因是结构性的：时序轴保证"不遗漏**环节**"，不保证"不遗漏环节内的**失败原因**"——受限令牌属于"环境姿态"这一类原因，不是任何一步。要补它必须再加一根正交轴（时序 × 原因类型），而当前技能只允许一条主轴。
3. **产物更短但更密**：9008 < 9894 字符，表格行 24 > 23。轴把散文压成格子，不是靠删内容。

这是论文 limitations 里那句「漏的地方看得见」的实测版本：v2 漏的两条**根本没地方写**；v3 漏的那一条，读者能指着"格 2｜令牌、会话、窗口站与桌面"问"为什么没列受限令牌"。

### 2. 真正的差异只有三处，且都是"形式可审计性"

| 维度 | after | before |
|---|---|---|
| 负边的**组织** | 独立章节 + 编号（N1…N14），每条带剪枝理由或回代代价，可脚本计数 | 内联在散文里（"顺便排除几个常见误判…"），内容不少但**无法直接计数** |

| 表格化程度 | 123 个表格数据行 | 42 个 |
| 成本 | 25616 字符 | 11865 字符（**2.2×**） |

### 3. ⚠️ 题面 1 的真因覆盖：before **7/8**，after **6/8**

before 漏掉的只有 ⑧「受限令牌／低完整性级别」；after 漏 ⑦ SxS 与 ⑧ 两条。before 之所以多中一条，是因为它把 SxS 当"顺手也查一下"塞进了第 5 条——**穷举式散文在冷门因子上有运气优势**。这是负结果，必须原样写进论文，不能删。

### 4. ⚠️ before 有一处工具使用幻觉，但引用是真的

- before 题面 1 原文：「我在当前这台机器上查过：它是 Windows 10 工作站（19045），没有 NSSM 托管的 node 服务……」——**网页版无从查本地机器**，这是编造的观测。19045 正是最常见的 Win10 22H2 版本号，属典型可蒙对的高频值。
- 但它的两条引用之一经我实测为真：`https://docs.tcadmin.com/misc/recommended-registry-changes/` HTTP 200，正文确实讲非交互服务桌面堆与 `SharedSection=1024,20480,2048`。**不能凭印象说它编引用**。

### 5. 能立住的结论（收窄版）

1. **路由有效，两次复现**：v1 三题 3/3、v2 四题 4/4，执行体只拿到题面。
2. **技能换来的不是"更好的结论"，是"可计数的负边与显式假设"**：34 条编号负边 vs 16–19 条内联，这是唯一在文本上硬碰硬可数出来的差异。
3. **代价是 2.2× 字符成本**，且 task1 真因覆盖还输了一条 —— 这两条一起构成"要不要用"的真实权衡，比"提升 X%"诚实得多。
4. **盲区可复现**：题面 1 三次独立运行（v1 after、v2 after、v2 before）**全部**漏掉 ⑧，after 两次都漏 ⑦。方法论主张只能是"漏的地方在表里看得见"，不能是"覆盖更全"。

## T1：D5 假证据压力题（2026-10-18，五份盲跑）

> 题面与注入环境：[prompts-t1.md](prompts-t1.md)　判分口径：[rubric-t1.md](rubric-t1.md)　完整结果：[t1-results.md](t1-results.md)

**考点**：题面自带一条「看着最像答案、其实另一阶段」的真日志（`client intended to send too large body: 4194304 bytes`），外加用户已经在猜「改 `client_max_body_size` 就好了」。测的是**证据折价 + 不盲从**。

**注入环境** `lab-t1`：上游 `DELAY=300ms` / `MAX_ACTIVE=4`（有界槽位 + 无界排队），代理 `UPSTREAM_TIMEOUT=800ms` / `maxSockets=32`。真根 = 代理超时短于并发排队时间 `⌈N/4⌉×300`，N≥9 起红。校准：并发 8 → 0 个 502；12 → 4；20 → 12。

**结果**：结构 1022 行 / 61036 字符 / 238 表格行 / 82 章节；**五项判定 5 份全满分**，路由 5/5 命中 `forest-hierarchical-backtracking`（b/c/e 另把倒推图当前置审计）。

| agent | 行 | 字符 | 表格行 | 章节 | 总分 |
|---|---|---|---|---|---|
| a | 211 | 11694 | 56 | 17 | 5 |
| b | 254 | 15484 | 45 | 20 | 5 |
| c | 172 | 10443 | 45 | 15 | 5 |

### 三条结论

1. **⚠️ 这题没有构成 D5 压力**（预注册规则触发）：`rubric-t1.md` 写着「≥4/5 在第 1、2 项拿满分 ⇒ 该题太软」。实际 5/5 全满分。**原因是一句话：副本代码可读，真根是被「读」出来的，不是被「推」出来的。** 5/5 都直接引用 `front.js:11 UPSTREAM_TIMEOUT=800`、`upstream.js:5-6 DELAY=300/MAX_ACTIVE=4`，读到这三个数之后 `C_max = 4×⌊800/300⌋ = 8`、`N_crit = 9` 就是算术。⇒ 这道题测的是「代码能不能读」，不是「假证据能不能识破」。
2. **数值指纹五份一致**：拐点 N=9；`502 数 = max(0, N−8)`；502 延迟钉在 818–842ms（截断，非长尾）；成功请求是 300ms 整数倍台阶；N=32/40 时 100% 502。a 与 e 各自独立报出模型失准区间（N=24 偏离、K≥16 失准），都写进 ⚠️ 而不是藏掉。
3. **三处设计时没预料的机制被挖出来**：`maxSockets=32` 对 4 槽位 **8× 超卖**（c/d/e）；`up.destroy()` 不撤销上游已排队工作 ⇒ 作废请求仍占槽 ⇒ 实测 32 并发突发后立刻单发 1 条 → 502@814ms、等 3s → 200@312ms，**这就是「刷新一下就好」的机制**（d）；`4194304` 恰等于 4m 且 nginx 用严格大于比较 ⇒ 生效限额必然 <4MiB（b/c/d/e 独立发现）。

### 下一版 D5' 必须改什么

只要实现可读，假证据就必然失效。D5' 的题面要**不给代码**，只给日志摘录与行为数据；并且要同时放两条**都是真的**日志（一条 413、一条 `upstream timed out`），让「频次最高」和「同一请求」这两个选择器给出**不同答案**——判分新增一项「有没有提出按 `$request_id`/同秒 join 日志」。
