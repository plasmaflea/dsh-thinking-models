# before / after 对照：结构化技能是否改变输出

## 这是什么

同一批问题，问两次：一次给**装了技能与工作区约定的宿主**（after），一次给**把技能和约定都撤掉的宿主**（before），两份原文并排，用**跑之前就定死的指标**数差异。

不是排行榜。每条件 n=1，单次运行，目标是**证明差异存在且可被计数**，不是"平均提升 X%"。

题面的**逐字定稿**在 [prompts-v2.md](prompts-v2.md)，本页只放摘要与结果。

## 四个题面

| # | 路由目标 | 题面（摘要） | 为什么选它 |
|---|---|---|---|
| 1 | 🌳 林状图 | NSSM 托管的 Node 服务启动即退，只有 `exit code 3221225794`，无堆栈无 stdout，env 与权限已查，根源在哪？ | **有客观答案**：`0xC0000142` = `STATUS_DLL_INIT_FAILED`，说不出码义就是没查到根 |
| 2 | 🕸️ 网状图 | 技术博客三年、月访问 800、AdSense 月入 5 美元，除「多写文章」外的增长路径 | **可判定覆盖**：路径类别（存量／分发／变现／形态／外链／定位）事后可数 |
| 3 | 📐 公式图 | 3 人 6 个月做 Notion 类块编辑器 MVP，大概多少人日 | **有量级答案**：3×6×20≈360 投入人日，不给假设等于拍脑袋 |
| 4 | 🧪 倒推图 | 结论「留存低是因为引导太长」，三条证据全不支持，老板要求下周立项 | **有可判定结论**：正确做法是判「不成立」并给出反例条件，而不是顺着给方案 |

## 指标（跑之前定义）

| 指标 | 定义 | 判据 |
|---|---|---|
| 路由 | 是否命中预期那一个技能 | 命中 / 未命中 |
| 成本 | 输出行数 / 字符数 | 脚本实测，不采信自述 |
| 结构产物 | 是否给出林／表／式 | 有 / 部分 / 无 |
| **负边** | 是否有独立的"已排除 / 无关 / 不成立"章节，每条带理由 | 条数 |
| 收敛判据 | 是否有"先查什么、什么条件下排除、什么条件下改结论" | 有 / 无 |
| 假设显式化 | 结论依赖的取值与前提是否写出、含"被推翻会怎样" | 有 / 无 |
| 编造证据 | 是否出现无法核实的数字／文件名／引用 | 有 / 无 |
| 命中真因 | 仅题面 1，对照下方 8 因子表 | x/8 |

题面 1 的 8 因子真因集：① 码值语义 ② `DllMain` 阶段失败（解释无堆栈无 stdout）③ Session 0／非交互窗口站 ④ 桌面堆 `SharedSection` ⑤ DLL 搜索顺序／影子 DLL ⑥ `AppInit_DLLs`／杀软注入 ⑦ SxS 配置错误 ⑧ 受限令牌／低完整性级别。

## 已经能看出的四件事

1. **路由有效，且是第二次复现**：v1 三题 3/3，v2 四题 4/4。执行体只拿到题面，没有被告知方法。
2. **负边是结构性差异，不是风格差异**：四份产物都有独立的负边章节（8／7／9／5），每条带剪枝理由或回代代价。自由推理通常没有这一节。
3. **⚠️ 结构化穷举也有稳定盲区**：题面 1 两次独立运行（v1、v2）**都**漏掉 SxS 与「受限令牌／低完整性级别」，命中同为 6/8，而后者恰是本机 DSH 沙箱 `0xC0000142` 的真实根因（`WRITE_RESTRICTED` + Low IL）。**盲区是可复现的**——这条比命中率更值得写进论文 limitations：方法论的主张不是"覆盖更全"，而是"漏的地方在表里看得见"。
4. **自述可信度不稳定**：v1 出现过自述 161 行、实际 212 行（偏差 51 行）；v2 四份自述与磁盘**完全一致**。所以指标一律脚本数，恰好这一条本身就是可报告的观察。

## 方法上的诚实声明

- 每条件 n=1，单次运行，LLM 有随机性；本页不放"提升百分比"。
- after 侧由**独立执行体**生成：只给题面（外加禁止读取本目录与 `examples/` 的屏蔽指令），不给方法提示；产物原样入库，作者只做计数、不改正文。
- 但**作者非盲**：写题面的人已经知道 v1 的结论与盲区。因此 after 侧的可信度依赖"执行体不知情"这一设计，而不是作者不知情。这一点必须写进论文。
- 若 before 侧改用网页版免费模型，则差异里会混入**宿主／工具／版本**三项，届时不能与 after 主表并列，只能作为"生态基线"单列。
- 行数、字符、表格行、章节、负边条目全部由脚本实测；负边条数为按章节解析所得，仍建议人工抽查一遍。
