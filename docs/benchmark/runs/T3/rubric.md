# T3（D10' 数据退化 / 口径陷阱）— 题面与判分口径

**预注册日期**：2026-10-18（跑之前写定，跑完不改口径）

## 一、为什么出这道题

D10 原设计是「根本身是分布」，需要按 API 路径分桶的数据，而**这类数据在真实事故里恰恰不留存**（网关按合规不留原始报文，只留聚合指标）。

所以 T3 不改数据粒度，改的是**数据本身的判别力**：厂商级的聚合指标全部保留，但**数据里不存在任何能把两个嫌疑分开的维度**。这是真实事故的常态，也是 v1–G3-alt 一直没测到的形态。

## 二、这一版数据踩了哪几个坑

| 编号 | 坑 | 说明 |
|---|---|---|
| P1 | **变换在数据自洽性里** | 明细表（原因族 48/43/9、端 38/22/40、地区 45/25/20/10）与聚合总表能带权重还原到 1.80% / 3.05%。做这个验算就能确认「明细可用」，不做就只能靠信。**且 3.05% 本身有三种拆法**，不同拆法指向不同根。 |
| P2 | **两个主嫌疑不可分离** | v3.4 发布与 CDN 切换在**同一分钟（10-08 20:00）**、都没有灰度、都改动全站面、都没有留存对照流量 ⇒ 聚合数据在数学上无法分开两者。硬要归因，必须新增观测。 |
| P3 | **纯加法失败** | 「网关超时 +1.790 − 风控 +0.026 + 其他 +0.298 = +1.250pp」。若某人写「各项相加正好等于 1.3pp，所以主要由超时驱动」，那是把**恒等式当成因果证据**，且最后一项是 `其他`——它正是被兜底掉的那部分。 |
| P4 | **误差不可追** | 网关原始报文不留存；失败原因族由网关侧回填，无法二次核对；风控拒绝「规则没动过」是口头说法。⇒ 任何「按路径分桶」的验证都**做不出来**，只能靠新增观测。 |
| P5 | **无干净对照组** | 切换后仍有部分请求走 A 节点，但数据**不给**「哪些区域走 A」的划分 ⇒ 想拿 A/B 当对照就得先自己找出划分，而数据里没有。 |
| P6 | **三个变更同期** | 10-08 20:00（v3.4 + CDN）、10-09 22:30（PG 13.6→13.7）、10-10 00:00（大促 +40%）。硬凑三重归因是另一种过度断言。 |

## 三、真实答案（对标准）

- **可判定**：三周前 1.80% → 本周 3.05%，增量的最大单项是「网关超时」（+1.06pp，占 81%）。
- **可判定**：v3.4 与 CDN 切换在同一分钟生效，且都没有对照流量 ⇒ **从这份数据里无法区分两者**。
- **可判定**：大促是乘数而不是根——10-11/10-12 周末失败率回落（97.95/98.00），而大促仍在进行。
- **不可辨识**：CDN B 回源劣化 / v3.4 下单页改动 / v3.4 BFF 优惠券校验重写 / PG 小版本 —— **四者在这份数据上不可辨识**。
- **必须新增的观测**：任一能把四者分开的动作（按 API 路径分桶、按发布灰度名单分桶、按节点组分桶、或直接做单变量回切实验）。

## 四、判分项（5 项，每项 0/1/2 分，满分 10）

| 项 | 判据 | 2 分标准 |
|---|---|---|
| **S1 数据自洽性验算** | 是否对明细表做了加权还原、并明确说「明细可用／不可用」 | 算出了 1.796→1.80、3.052→3.05，或等效地指出三张明细各自加权均吻合 |
| **S2 不可辨识性声明** | 是否明确说「v3.4 与 CDN 在同一分钟、无对照 ⇒ 这份数据分不开」 | 明确写出「不可区分／不可辨识」，并指出原因是同一窗口 + 无对照 |
| **S3 不把自己的加法当因果** | 是否避免「各项相加=1.3pp，所以主要是超时」这种恒等式冒充因果 | 指出占比分解是记账、不是机制；或指出「其他」列是被兜底项 |
| **S4 乘数 vs 根** | 是否把大促/负载判为放大项而非根 | 用周末回落（10-11/10-12）或其它证据说明负载不是根 |
| **S5 下一步是「买信息」而非「赌一个根」** | 只能做一件事时，第一步是不是去拿到能分开四者的观测 | 明确给出可执行的分离观测（路径分桶/灰度/单变量回切/节点组分桶之一），并说明它分开谁 |

## 五、预注册判定规则（跑完按此读结果，不改口径）

- **R1**：若 ≥3/5 份写出「不可辨识」⇒ 技能在「数据判别力」这一维有效。
- **R2**：若 ≥4/5 份自动做数据自洽性验算 ⇒ 有 P1 触发的自检习惯。
- **R3**：若 ≥3/5 份在没有能力分开四者的情况下**仍然断言了单一根**（且未声明不可分离）⇒ **过度断言**，进 paper 的 limitations，并考虑在技能里加「先验数据判别力」前置。
- **R4**：若 ≥4/5 份正确加载知识树并写出真实路径（含 `路径` 字段）⇒ 路径修复有效。
- **R5**：若 ≥4/5 份只给出「先排查 X」而没有说明该观测能分开谁 ⇒ 技能的验证环节只在题面已知码位时有效，这是新盲区。
- **R6**：知识树缺口（`network` / `data-consistency` / `payment-flow` 均待建）若 ≥3/5 份主动登记为标记候选 ⇒ 树的待建节点设计有效。
