## 四、四条实打实的发现

### 发现 1（最重要）：技能会**审计数据本身**，而人类在这个位置上会直接算

5 份里 4 份（a / c / d / e）独立发现了同一处算术不可能：

> 三周前各端失败率最小 **2.8%**、各地区最小 **2.9%**，而聚合失败率只有 100−98.2 = **1.8%**。加权平均**不可能低于最小值** ⇒ 两张明细表与总成功率**不是同一个分母**。

- a 把它推到底：还发现「27% 的 504 与网关 p95 325ms 算术不相容」「把 1.3pp 全归海外需 `w_海外≈23%`，而端表反解要求 Web 占 54%~74%，两法互斥」⇒ 直接判定**这套观测结构不允许定因**。
- c 给出正确处置：**只能读方向，不能换算 pp**。
- d 更进一步，把「各方吵两周」的机制归因到这处不自洽。
- b、e 也各自用恒等式做了闭合校验（b 的分解表精确闭合到 +1.300pp）。

**这是我对这批数据的设计失误**（见第五节），但它反过来成了本项目的强证据：**结构化技能在拿数据开算之前，先检查数据能不能算。** 这一点在 v1–v4 的所有题里都没被触发过，因为那些题的数据是自洽的。

### 发现 2：我白送了一个对照组，5/5 全接住了

数据里我随手写了一行「CDN 首字节 p95（**仍走 A 节点的区域**）：180ms → 180ms，未变」。这句话等于：

> 同一时刻、同一套代码，只有入口节点不同；B 组 420ms，A 组 180ms 纹丝不动；而海外失败率 3.2%→8.9%、国内三区只有 +0.2/+0.2/0.0。

5/5 都把这条当成**天然对照实验**，并据此把 CDN 定为主因——这个推理是**对的**。所以本题的正确答案不是「无法定根」，而是「CDN 边缘劣化 + 客户端短超时 + 大促放大的两段式」。**我的题面设计与 D10 的意图相反。**

### 发现 3：埋的辛普森陷阱，5/5 全部拆穿

「风控拒绝占比 43%→21%」看起来像风控放宽，实际是**分母被撑大**：

| | 基线绝对率 | 当前绝对率 | Δ |
|---|---|---|---|
| 网关超时 | 0.864% | 1.922%–2.108% | **+1.06 ~ +1.24pp** |
| 风控拒绝 | 0.774% | 0.651%–0.714% | **−0.06 ~ −0.12pp（下降）** |
| 其他 | 0.162% | 0.527%–0.578% | +0.37 ~ +0.42pp |

5/5 全部做了「份额 × 总失败率 → 绝对率」的折算，并得出同一结论：**风控不是嫌疑人，是分母效应的受害者**。e 还给了机制名（「失败前移：请求死在前面的跳，没走到风控」），d 直接写「风控被算术排除，Cost=0，可以结案」。

## 五、两处必须承认的设计失误（比结果更重要）

### 失误 1：数据算术不自洽（我的锅）

我写 `data.md` 时按「端/地区各自恶化」构造，忘了它们必须加权还原到总失败率。结果：

- 三周前：端 3.4/3.0/2.8、地区 2.9–3.3，**全部高于**总失败率 1.8% ⇒ 不可能。
- 本周：地区最小 3.1% 恰等于聚合 3.1%，但海外 8.9% ⇒ 要求海外权重为 0 ⇒ 不可能。

**后果**：本题所有「份额 → pp 贡献」的推断都建立在不可靠的明细表上。4/5 的 agent 发现了并降低了对它的依赖，1 份（d）仍用它算了 78% —— 那份的分解数字必须打折看。

### 失误 2：rubric 第 2 项的前提是错的

我写第 2 项时假定「Web 是 CDN 最敏感的端，Web 改善 ⇒ CDN 不是根」。但 A/B 对照组存在时，正确推理是反过来的：**CDN 只影响了 B 节点区域，Web 用户大多在 A 节点区域，所以 Web 改善说明「v3.4 不是根」，不说明「CDN 不是根」**。

5/5 的 agent 都选了后一种读法——它们是对的，我的 rubric 是错的。按字面判，这份 rubric 会**惩罚正确答案**。这是本轮最有教育意义的一条：**判分表本身也会带着作者的因果假设，而这个假设可能错。**
