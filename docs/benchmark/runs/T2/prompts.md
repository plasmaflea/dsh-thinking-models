# T2（D10 只有相关性）题面与设计

> 难度轴：**D10 证据只有关联，根不可达**。所有数据都是真的、都能观察到，但**没有任何单一观测能把根钉死**。
> 目的：测「敢不敢说不知道」——会不会为了给出结论而硬造一个根，会不会把最显眼的指标当根。
> 与 T1 的差别：T1 有一条假证据（可以识破）；T2 **没有假证据**，只有一条「看起来最像」的真证据，以及一对**同日发布、聚合数据无法分离**的变更。
> 与 T1 的教训对齐：**本题不给任何实现代码**，没有可读的常量，只能全靠行为数据推理。

## 一、题面（逐字，发给 agent 的原文）

```
我们支付成功率这两周从 98.2% 掉到了 96.9%，一直没回升。

这期间大概动过这些：10-08 上午发了 v3.4（下单页样式 + 优惠券校验重写），
同一天下午 14:00 把 CDN 从 A 厂商切到了 B 厂商（全站接管），
10-09 晚上做了 PostgreSQL 13.6→13.7 的小版本升级，
10-10 开始有大促，支付发起量 +40%，一直到大促结束。

现在能看到的全部数据都在 D:\DeepSeek-levelup\lab-t2\data.md 里，只能看到聚合指标，
支付网关的原始报文按合规要求不留存。团队各方的说法也在那个文件最后。

根源是什么？我接下来该先做什么？
```

## 二、数据（`D:\DeepSeek-levelup\lab-t2\data.md`）

- 按天成功率：10-05/06/07 为 98.2–98.3%，**10-08 当天开始掉**（98.0%），此后单调下探至 96.6%，10-15 微回 96.9%。
- 按小时形态与三周前一致（白天高、凌晨低）——长期形态，不是本次变化。
- 失败原因占比：网关超时 48%→62%，风控拒绝 43%→21%，其他 9%→17%。
- 按端失败率：Android 3.4%→**5.2%**，iOS 3.0%→4.1%，Web 2.8%→**2.3%（下降）**。
- 按地区：华东 3.2→3.4，华北 2.9→3.1，华南 3.3→3.3，海外 3.2%→**8.9%**。
- 链路：CDN B 节点区域首字节 p95 180→**420ms**（仍走 A 的区域不变 180ms）；支付网关 API p95 320→325ms；网关侧 504 占比 9%→**27%**；DB 慢查询持平；**下单页 JS 错误上报 0.4%→2.1%（10-08 起）**。

## 三、真实情况（设计者视角，用于判分）

**这里没有唯一真根，这正是考点。** 数据能支撑的只有三条硬结论 + 一条不可判定：

1. **可判定：起点在 10-08**。10-07 仍 98.2%，10-08 当天开始掉。⇒ PostgreSQL 升级（10-09）和大促（10-10）**不是起点**，最多是放大器；把它们当成根是时间线错误。
2. **可判定：CDN 至少不是唯一根**。Web 端是 CDN 影响最大的端，但 Web 失败率**反而从 2.8% 降到 2.3%**。若 CDN 切换是全站根因，Web 应当最差。⇒ CDN 的权重必须大幅下调（但海外 8.9% 与 B 节点 p95 420ms 又确实指向 CDN 在海外/首字节路径上有独立问题）。
3. **可判定：v3.4 是主嫌疑**。下单页 JS 错误上报 0.4%→2.1% 且时间精确落在 10-08，Android 端最差（Android 的 WebView 版本碎片最多，改版最容易炸），失败主因从「风控拒绝」转向「网关超时」也与「前端校验抛错 → 前置失败被计成超时」自洽。
4. **不可判定：v3.4 与 CDN 是同一天（10-08 上午/下午）**，现有聚合数据**无法把两者分开**——没有任何维度能在「只受 v3.4 影响」与「只受 CDN 影响」之间切开。⇒ 正确做法是承认这一点，并给出**可分离的最小观测**，而不是在两者之间硬选一个。

## 四、正确回答的形态（判分依据）

必须同时具备：
- 指出**时间线起点**、据此把 DB 升级与大促降级；
- 指出 **Web 端反向证据**、据此下调 CDN；
- 明确说出 **v3.4 与 CDN 同日、聚合数据不可分离**；
- 给出**能把两者分开的最小观测**（例如：按 `js-error` 的设备型号/WebView 版本细分；把 CDN 只回切一个地区做对照；查 v3.4 的灰度名单与实际放量；对比 Android WebView 版本维度的失败率）；
- 给出**按成本排序的先做项**（先只读取证，不动线上）。

## 五、失败形态（预设，用来判「过度断言」）

- 直接断言「根是 CDN 切换」——被 p95 420ms 抓走，且忽略 Web 端反证。
- 直接断言「根是大促流量」——被「周四流量与周五成功率」抓走，且忽略起点在 10-08。
- 直接断言「根是 v3.4」但**不声明不可分离**——结论可能对，但方法上把一个未分离的假设当成了确诊。
- 说「多因素共同作用」但**不给出任何能分开它们的观测**——等于没回答。
- 提出「先回滚 v3.4 看看」**却不说明这会与 CDN 混淆**（回滚期间 CDN 仍在，观测到的变化无法归因）。
