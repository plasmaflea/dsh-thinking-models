# 守恒 / 账本（`conservation`）

**边型**：`Δ存量 = 流入 − 流出`（加性守恒，等号必须平）

**变量集**
- `流入`：进入系统的量（到货、到达请求、收入、分配额度）
- `流出`：离开系统的量（发货、完成、支出、被消费）
- `存量`：留在系统里的量（库存、积压、余额）
- 可选：`丢弃/旁路`（超时、丢包、未记账分支）

**边界条件（缺一即非本模式）**
- 系统边界清晰（什么算在内、什么算在外，能说清）
- 时间窗内**没有不记账的分支**（旁路必须显式列出，哪怕记为零）
- 计量单位一致（件/单/元/秒不能混算）
- 允许延迟，但延迟本身要记账（在途量）

**已知同构问题**
- 库存对账：`期末 = 期初 + 入库 − 出库`
- 请求守恒：`入口 QPS = 成功 + 失败 + 丢弃 + 在途`
- 资金流：`余额 = 充值 − 消费 − 退款`
- 上下文预算：`可用窗口 = 上限 − 系统提示 − 工具结果 − 历史`

**该类的典型处置动作**
1. **用差值定位，不要用总量定位**：「账不平的那一段」就是根因范围，比看任何单点指标都快。
2. 先补记账再谈优化：不记账的分支会让守恒式永远不平，此时任何结论都不可信。
3. 若账平但结论与直觉冲突，问题在**计量单位**，不在数量。
4. 结论形式：`哪一段差了多少，差值的量级是否在观测误差内`。

**越界后退化成什么**
- 存在未记账旁路（影子流量、私账、体外循环）→ 先补账；补不上就只给上下界。
- 出现重复记账（重试被算两次）→ 换 `queue-capacity`（重试是放大因子）。

**反例（别把它当本模式）**
- 「用户投诉数 = 故障数」——投诉只是失败的一个子集，不是守恒关系。
- 「库存少了 9 件」直接等于「卖超 9 件」——若同时有入库延迟，差值可能来自在途。
