# 饱和 / 非线性（`saturation`）

**边型**：`成本 ∝ S · f(ρ)`，最常用形式 `W ≈ S/(1−ρ)`、`Wq ≈ S·ρ/(1−ρ)`（凸、单调、ρ→1 时发散）

**变量集**
- `ρ = λ/μ`：利用率（到达率 ÷ 服务能力）
- `S`：单次服务时间 / 单件成本
- `λ`：到达率；`μ`：服务率
- `W`：等待/响应时间（或成本）

**边界条件（缺一即非本模式）**
- **稳态**：观测窗口足够长，没有持续增长的积压
- 到达近似平稳（突发会改变二阶矩，本模式只吃一阶）
- 服务时间近似独立同分布
- 队列（近似）无界且不丢弃
- `ρ < 1`（ρ≥1 时系统不收敛，给不出有限延迟）

**已知同构问题**
- M/M/1 排队：`W = S/(1−ρ)`
- CPU 利用率 vs 响应时间；连接池/线程池等待
- 团队负荷 vs 交付时间（负荷 > 85% 后延迟非线性上升）
- 重试风暴：有效到达率 `λ_eff = λ × 平均尝试次数`

**该类的典型处置动作**
1. **先算 ρ 再看倍数**：任何「+x% 负载 → y 倍延迟」的断言，都必须先给出 ρ。
2. `ρ > 0.85` 之后，优化优先级是**降 ρ**（扩容、限流、削峰），其次才是降 `S`。
3. 用观测倍数**反解 ρ**，是这类问题最省的取证方式（例：延迟涨 4.5× ⇒ ρ 从 0.78 到 0.95 量级）。
4. 结论形式：`ρ 的当前值 + 还有多少 headroom + 越过临界点后放大的量级`。

**越界后退化成什么**
- 到达突发（二阶矩高）→ 只能给量级，须换 Kingman 近似或实测。
- 有界队列/超时丢弃 → 观测到的是截断值，不是真实延迟。
- ρ≥1 → 系统不收敛，此时「延迟」无定义，只能说「必然持续积压」。

**反例（别把它当本模式）**
- 「加 9% 负载导致 4.5 倍延迟」——只在 ρ 已接近 1 时成立；ρ=0.5 时加 9% 几乎无感。
- 把人力负荷当排队：人力超载是加班/降质，不是排队等待（见 `queue-capacity` 的反例）。
