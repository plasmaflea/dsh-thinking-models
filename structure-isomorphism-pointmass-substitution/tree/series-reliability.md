# 串联可靠性（`series-reliability`）

**边型**：串联 `R = ∏ rᵢ`（乘性，但因子是**存活概率**）；并联 `R = 1 − ∏(1 − rᵢ)`。
整体 ≈ **最弱环 × 环节数**。

**变量集**
- `n`：环节数（含"没想到的环节"，这是最大风险）
- `rᵢ`：单环可靠度
- `k`：冗余路数（并联）
- `MTTR`：修复时间（决定可用度而不只是可靠度）
- 检测覆盖率：失效能不能被发现（发现不了 = 等于 100% 失效）

**边界条件（缺一即非本模式）**
- 失效**独立**（相关失效会让 `∏` 严重高估）
- 环节**可枚举**
- 失效是**二值**（不是降级运行）
- 时间窗内无维护（有维护要按可用度 `MTBF/(MTBF+MTTR)` 算）

**已知同构问题**
- 供应链：n 级供应，任一断则断
- 项目交付：每个依赖都要按时
- 飞机/手术/发射：单点失效即灾难
- 安全：纵深防御（串联攻击面）vs 冗余（并联）
- 关键人依赖：bus factor
- 数据备份：3-2-1 冗余，但同机房 = 相关失效

**该类的典型处置动作**
1. **先算 `n` 和 `r`，再谈"加强"**：串联可靠度是**乘出来的**，`n` 大时再高的 `r` 也会掉（10 个 99% 串联 = 90.4%）。
2. 优化顺序：**减少环节数 > 提高最弱环 > 加冗余**。加冗余排最后，因为它引入新的相关失效（同源、同批、同人）。
3. 冗余只在**失效独立**时有效；不独立时，冗余只是"多准备几个同样的篮子"。
4. 结论形式：`n 与各 r + 整体 R 的量级 + 最弱环 + 相关失效在哪`。

**越界后退化成什么**
- 失效相关（同机房、同供应商、同一人）→ `∏` 高估，只能给上界
- 环节不可枚举（未知未知）→ 只能算"已知部分"，整体不可算
- 降级运行（部分失效仍可用）→ 换多状态/加权模型，本模式只给下界
- 维护可改变失效率 → 按可用度算，不按可靠度算

**反例（别把它当本模式）**
- 「每个环节都是 99.9%，所以整体很好」——10 个串联只剩 99%。
- 用冗余解决人为操作失误：同一批人会重复同样的错误，冗余无效。
- 把"加监控"当可靠性提升：监控提高的是**检测覆盖率**，不提高 `r`；没有修复能力时只是知道得更早。
