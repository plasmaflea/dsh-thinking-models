# 搜索地形（`search-landscape`）

**边型**：**无闭式**。`当前 = 局部最优（∇f = 0）`；`全局 − 当前 = 地形多峰性 × 探索成本`。
决策变量是**探索率 ε**、重启次数、起点多样性，不是"努力程度"。

**变量集**
- 选项空间（大小、结构、可枚举否）
- 评估函数 `f`（可算否、可靠否、会否被行动改变）
- 局部最优个数（几座峰）
- 探索成本（试错代价、时间、机会成本）
- 已投入（沉没成本，会扭曲评估）
- 邻域结构（"相邻选项"是什么，决定能不能爬到隔壁峰）

**边界条件（缺一即非本模式）**
- 评估函数**已知且可算**（否则是 `signal-inference`，不是搜索）
- 地形**多峰**（单峰直接爬坡，不需要本模式）
- 探索有成本且**不能完全并行**（能穷举就没有地形问题）
- 邻域定义清楚

**已知同构问题**
- 创新/研发：技术路线是地形，局部最优是"够用但不够好"
- 招聘/择偶：候选人空间 + 评估不可靠
- 战略选择：商业模式地形
- 调参/超参搜索：典型多峰
- 职业路径：换赛道 = 跳峰（必须先下坡）
- A/B 测试：局部改进 vs 新方向
- 路径依赖：早期选择锁死后续可达集

**该类的典型处置动作**
1. **先判"是没找到"还是"根本没有"**：区分搜索不足与"地形只有这一座峰"，是最贵的一步，也是唯一值得先做的一步。
2. 三条杠杆按成本排序：**加探索（ε↑、重启、多起点）> 改地形（改目标函数/改邻域）> 换地形（换赛道）**。多数人只做第一条，因为便宜。
3. 跳峰必须**先下坡**：从局部最优到全局最优的任何路径都要经过更差的中间态；**不能接受"暂时变差" = 永远到不了**。
4. 结论形式：`当前峰的高度 + 已知几座峰 + 跳峰的下坡成本 + 探索预算（时间/钱/次数）`。

**越界后退化成什么**
- 评估函数噪声大 → 叠 `sampling-error`，只能给"多试几次"的预算，不给"最优"结论
- 地形会因你的行动改变（对手/市场反应）→ 叠 `adversarial-game`，静态地形假设失效
- 选项空间不可枚举/不可定义 → 转定义前置，本模式不适用
- 评估函数不可公度（价值冲突）→ 不是搜索问题，是不可公度问题（见库边界）

**反例（别把它当本模式）**
- 「更努力就能更好」——在局部最优上更努力，只是把同一座山爬得更陡。
- 把"选择困难"都当搜索：若评估函数本身无法定义（两种好无法比较），那是不可公度，不是多峰。
- 「多试就行」——若 `f` 有系统性偏（只测到局部），多试只是把同一个峰测得更准。
