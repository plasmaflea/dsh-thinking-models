# 加性预算分解（`additive-budget`）

**边型**：`Σ hᵢ ≤ B`（加性；并行段改 `max` 合成）

**变量集**
- `B`：总预算（时延预算、上下文窗口、内存上限、工期）
- `hᵢ`：各段消耗（DNS、TCP、TLS、TTFB；系统提示、工具结果、历史）
- `headroom = B − Σhᵢ`：安全余量

**边界条件（缺一即非本模式）**
- **串联**路径：各段依次发生、不重叠（并行段要用 `max` 而不是 `sum`）
- 各段消耗近似独立（某段变慢不改变其他段的消耗）
- 同一时间窗内没有重试放大（重试是乘性叠加，不是加性）
- 预算恒定（不是随负载变化的动态预算）

**已知同构问题**
- 端到端时延：`DNS + TCP + TLS + TTFB + 渲染 ≤ 用户耐心`
- 上下文预算：`系统提示 + 工具结果 + 历史 ≤ 窗口上限`
- 工期关键路径：关键路径各段之和 ≤ 交付日
- 内存预算：常驻 + 缓存 + 峰值临时 ≤ 上限

**该类的典型处置动作**
1. **用最大项定位，不用平均值**：先把各段实测出来，最大的那段才是优化对象。
2. **留 headroom**：预算用满即等于没有预算；给 15–25% 余量，尤其在会出现突发放大的链路上。
3. 先测分段再加总——没有分段实测的「端到端慢」不可归因。
4. 结论形式：`各段实测 + 最大项 + headroom + 哪一段一涨就会击穿`。

**越界后退化成什么**
- 有并行/流水 → 改 `max` 合成，总时间由最慢段决定。
- 有重试放大 → 乘性叠加（`实际 = 名义 × 平均尝试次数`），或换 `saturation`。
- 预算动态（自适应超时）→ 分段实测仍有效，但固定预算的结论失效。

**反例（别把它当本模式）**
- 「网关 p95 没变，所以网关没问题」——p95 是分位，不是预算消耗；若失败请求被超时截断，p95 反而会「看起来正常」。
- 把重试当成又一段预算：重试是乘性放大，加进去会把模型算偏一个量级。
