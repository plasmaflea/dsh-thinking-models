# 示例：🧪 预设答案假设倒推法（倒推图／倒推法·反面教材）

> 技能 id：`presupposed-answer-hypothesis-backderivation`

## 输入

> 我们的技能仓库已经能在 skills.sh 上安装了，说明这个方向肯定有人要。所以下一步应该直接做付费课，对吧？

## 产物

```
[🧪 倒推图] 审计对象：「能在 skills.sh 安装」⇒「这个方向肯定有人要」⇒「应该做付费课」
     注意：这段推理的结论（做付费课）出现在证据之前，属于典型倒推结构。

| 假设 H | 期望证据 E+ | 实际证据 E± | 差异 | 反例条件 |
|---|---|---|---|---|
| H1：能上 skills.sh 说明需求存在 | 安装数 >0 且持续增长 | 未检索（安装数未知） | 无证据，不是「有证据」 | 上线 2 周安装数 = 0 |
| H2：装过的人会用 | 有使用者反馈、issue、star | 未检索 | 无证据 | 出现「装了但没触发」的反馈 |
| H3：用过的人愿意付费 | 有人问「能不能买/有没有进阶版」 | 未检索 | 无证据 | 有人明确说免费够用 |
| H4：付费课的替代品不强 | 该细分没有现成课程 | 未检索 | 无证据 | 已有同类课程且评价高 |

标注：
  - 显式假设：无（原句没有一个「假设」字样）
  - 伪装成事实的假设：「说明这个方向肯定有人要」——「说明」二字把 H1 直接升格为事实

走形命中：
  #5 假设升格为事实 —— 「已经能安装」→「说明肯定有人要」，中间跳过了 H1 的检验
  #2 确认性检验 —— 四个假设全部标「未检索」，说明从未去找反例
  #1 单一假设 —— 只考虑了「有人要」这一支，没有并列考虑「没人要」「有人要但不付费」两支
  #6 循环论证 —— 「有人要」既是结论，又是「做付费课」的论据

纠正映射：
  #5、#4 → 公式图：先把判据写死（安装数达到多少才算有需求？谁定的阈值？）
  #1 → 穷举法：把「需求状态」的三支（无需求／有需求但不愿付费／愿意付费）穷举并列
  #2、#6 → 林状法：为「愿意付费」找独立的根（谁付过钱给什么东西），不用「有人要」当论据

结论：
  这份推理不可信，但不是因为结论错，而是因为它**还没有被检验过**。它把「可安装」当成了「有需求」的证据。
  下一步动作（按成本排序）：
  1. 查真实安装数（skills.sh 页面 / GitHub traffic）——这一步 5 分钟，能直接判死 H1
  2. 把「需求」拆成三支，各写一条反例条件
  3. 只有 H3 出现「有人主动问价」这种无法伪造的证据，才允许讨论付费产品
```

## 为什么这样比直接反驳好

- **不否认结论**，只指出「它还没被检验」——避免了「你说得对/不对」这种没法收场的位置
- **每条假设都有反例条件**，所以「下一步做什么」是自动出来的，不是额外发挥的
- **它抓的是语言层面的证据**：「说明」这个词就是假设升格的指纹，比读完整篇论证更省力
- **纠正映射指向具体模型**：诊断完立刻知道该用穷举法补假设集、用林状法找独立根，而不是笼统地说「要客观」
