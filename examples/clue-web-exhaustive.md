# 示例：网状线索关联穷举法

## 输入

> 小程序上线两周，次日留存 18%，行业均值 35%。有哪些可能？还有什么没考虑到？

## 产物

```
[🕸️] 选择理由：问的是「有哪些可能」，要的是覆盖度而不是单一结论；且线索之间有关联（渠道→人群→内容），
     适合建网后穷举。

| 线索 | 假设 | 证据 | 可能性 | 结论 |
|---|---|---|---|---|
| 渠道结构 | 买量占比高，人群与产品不匹配 | 后台渠道表：自然流量仅 12% | 高 | 保留 |
| 首启体验 | 首屏加载 >3s 导致次日不回 | 需查首屏耗时分位 | 中 | 待验证 |
| 价值到达时间 | 用户当天没触达核心功能（如建第一个项目） | 埋点：D1 核心功能触达率 23% | 高 | 保留 |
| 通知触达 | 无召回触点，纯靠用户自发 | 未接订阅消息 | 高 | 保留 |
| 统计口径 | 留存定义与行业口径不一致（新用户 vs 全量） | 需核对分母 | 中 | 待验证 |
| 竞品替代 | 同类小程序在做补贴，短期分流 | 无直接数据 | 低 | 排除 |

收敛（保留项按杠杆排序）
  1) 价值到达时间——触达率 23% 意味着大多数人在第二天没有回来的理由
  2) 渠道结构——自然流量占比过低时，留存本质是买量人群质量指标
  3) 通知触达——零召回手段，等于放弃次日

待验证
  - 首屏耗时 p75（决定是否进入保留项）
  - 留存分母口径（决定 18% 这个数字本身是否成立）
```

## 为什么这样比直接回答好

- 每一行都有状态，没有一行悬空——「不确定」被显式标成 `待验证` 并写明缺什么证据
- 「统计口径」这一行是穷举才逼出来的：直接回答往往会照着 18% 这个数字往下推
- 排除项也留档，说明不是没想到，是想过并剪掉了
