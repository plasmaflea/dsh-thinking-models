# 知识树索引（常量 · 用于回溯法 L1 实例化）

> 使用规则：先读本索引，再按需读命中的节点文件；产物必须写出 `树 = <节点> · vN · 核查 <日期> · 路径 <实际文件路径>`。
> 树里没有的分支 → 登记为「树外分支」进挂起表，不许静默丢弃；需新增节点时登记为 `v(N+1) 候选` 并写理由。
> 本树是**常量**：改结构要升版本，并在节点文件里写清改动理由与核查日期。

**树版本**：v2 · 核查 2026-10-19

## 怎么读：两条轴，先族后域

| 轴 | 管什么 | 缺失时怎么办 |
|---|---|---|
| **族轴**（恒等式族） | 决定 **L2 用哪条轴切**：一族给一个轴模板 | **不可缺**。判不出族 ⇒ 走建树慢档，不许硬套最近的族 |
| **域轴**（领域节点） | 提供该领域的**症状词表与先例** | **可缺**。缺域只影响措辞与案例，不影响轴；症状现描述并登记为树外分支 |

为什么分两轴：回溯法的轴只能由**恒等式**生成（时序是「时段之和」这个恒等式的特例）。所以「怎么切」是可迁移的常量，落在族轴；「这个领域长什么样」不可迁移，落在域轴。

**v1 的顶层轴缺陷**：v1 只有域轴（`software`／`win-service`），于是除软件题外一律无树可用——这不缺节点，是缺了一层轴。v2 把族轴补为顶层。

## 族轴（恒等式族 · v2 新增）

| 族 id | 轴模板（L2 直接照抄） | 选中判据（满足其一即选） | 节点 |
|---|---|---|---|
| `time-decomposition` 时间分解 | 阶段 1 → 2 → … → n | 有必经顺序、不能并行、能指出「上一步完成才算进入下一步」 | 未建（族已定） |
| `additive-cost` 成本分解 | C总 = C₁ + C₂ + … + Cn | 总量能拆成互斥、可分别归属的支出项 | 未建（族已定） |
| `multiplicative-supply` 供给分解 | 产出 = 需求 × 转化率 × 留存 | 有链式放大，且任一环可断导致全链归零 | 未建（族已定） |
| `rationing` 配给分解 | 产出 = 位置稀缺 × 分配装置 × 承担者 × 退出选项 | 有人在排队／有人拿不到／有可观测的准入规则 | **[rationing.md](rationing.md)** · v2 |
| `game` 博弈分解 | 结果 = 参与人 × 支付 × 规则 | 有人能靠改变他人预期获益（不必自己变强） | 未建（族已定） |
| `information` 信息分解 | 信号 = 真实值 × 噪声 × 验证成本 | 有冒充、有逆选择、有认证 | 未建（族已定） |

**族判错的代价高于域判错**：族定轴，轴错则整张林状图重画。所以判族只许按上表判据，**不许按题面主题词**（「教育」「医疗」「招聘」「高考」都不是族名，它们只是域或场景）。

**一个题可以同时命中多族** ⇒ 取**约束层所在的那一族**（判据：哪一族的某格一旦改掉，其余族的问题自动缓解），其余族登记进挂起表，不许静默丢弃。

## 域轴（领域节点）

| 节点 | 文件 | 覆盖范围 |
|---|---|---|
| `software` | [software.md](software.md) | 软件类问题的判据与六个正交子层（生命周期／初始化／依赖／配额／并发／配置） |

## 节点文件的必备字段（v2 升级：字段不齐就退回候选）

| 字段 | 内容 | 缺了会怎样 |
|---|---|---|
| 节点 id · 父节点 · 版本 · 核查 | 能回填进产物四元组 | 结论不可复核 |
| **判据（怎么观测）** | 能退化成 yes/no 的问句，附**排除项**（先排除再进入） | 没有判据的分类是标签，标签会互相污染 |
| **轴格表** | 每格：格名／在管什么／**必查或选查**／**上游或下游**／**硬否决条件**／该格失效的**可观测症状** | 缺症状 ⇒ 判不出「这格到底有没有问题」；缺硬否决 ⇒ 判不出「这族成不成立」 |
| **根类型表** | 每个候选根标 `发生`／`维持`／`杠杆`／`归责` 之一 | 「根」字混义，必然出现「中段能不能当根」的争论 |
| **默认 `G` 与类的所有者** | 本类问题默认锁谁的目标；换 `G` 必须明示 | 默示 `G` 是最坏形态 |
| **常配结构模式** | 与结构表的哪些模式组合出现（**只写模式 id**，不复制内容） | 两棵树各走各的，无法互相校验 |
| **先例（含反例）** | 至少一正一反；库外先例必须标来源 | 只有正例 ⇒ 确认性检验 |
| **检索指令** | 该查什么、去哪查（**不存数字**，数字必过期） | 抄旧数字 = 编数 |

### 根四型（不许只写「根」）

| 型 | 回答 | 用在哪 | 判据 |
|---|---|---|---|
| `发生` 发生根 | 为什么会有这一类 | 消解根的「不可发生判据」 | 去掉它，本类结构上不可能出现 |
| `维持` 维持根 | 为什么它没有自愈 | 解释长期存在、解释「改了又回来」 | 去掉它，问题会在若干周期内自行消失 |
| `杠杆` 杠杆根 | 从哪下手最省 | 处置根、可执行首边 | 动它一次，多个症状同时缓解 |
| `归责` 归责根 | 谁的目标在维持它 | 锁 `G`、找否决方 | 能指名到「谁签的字／谁的利益」 |

同一段因果常常同时是四型，但**必须标明是哪一型**。「中段当根」有时正确（中段恰是杠杆点），错在不标明。

## 三条硬约束（v2 新增，用来替代权重）

1. **不加权重**。权重是预算的函数（技能 §8「排序是预算的函数」），随场景变；本树是常量，常量里放变量 ⇒ 每次用都要重校 ⇒ 退化成凭感觉打分。
2. **用「必查／选查」代替权重**。必查格在任何同类问题里都要查，不许因「这题看起来不像」而跳过；选查格按域补。
3. **用「上游优先」代替权重**。格子标序，先查上游。**上游空而下游有症状 ⇒ 上游的判据写错了，回头改判据，不许接着往下查。**

「权重」在本树里唯一合法的位置是负向经验：节点里写「本形态最常被判成 X」——它防误判，不参与打分。

## 判类三道闸门（缺一即错，顺序不可换）

1. **判族**（本索引 §族轴）——定轴。判错全盘错。
2. **切格**（节点 §轴格表）——每格必须有症状或「此处无症状」。
3. **交付前自检**（技能正文 §10 六问闸门）——题面回读、轴格与锚点、挂起表恢复条件。实测三次错全出在第三道：前两道都做了，交付前没自检。
