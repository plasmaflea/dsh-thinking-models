# 🌳 林状分层分类回溯法

**简称**：林状图（产物）／回溯法（方法）
**技能 id**：`forest-hierarchical-backtracking`＝森林·分层·回溯，与全称的三段结构一一对应

## 这张图是什么

一张有向无环的因果图——多根森林。它填的是**纵向关系**：谁导致谁、谁是谁的必要或充分条件、谁与谁已被排除。

产物不是一段推理，是一张**关系图 + 挂起表**。

## 关系语法（先定语法，再填格子）

只允许两种边：

- **因果边** `A → B`：A 是 B 的必要条件或充分条件，必须标明是哪一种；标不出，说明这条边是猜的
- **挂起边** `A ⊥ B`：判定 A 不是 B 的根。必须写满四列——**分支 / 判定 / 依据 / 恢复条件**。写不出恢复条件，说明这只是"没想到"，不是"已排除"

禁止跨维度边。不同维度只在**汇合层**合并。

## 四种动作

1. **选轴（生成式，不是列举式）**——轴必须由**必经过程**或**恒等式**机械生成，不得靠想到什么列什么；每格必须写出「该格故障的可观测症状」。生成源只有两类：
   - **时序／流程**：一步必然发生且只发生一次（服务启动、一次请求、用户旅程）
   - **恒等式／结构式**：`收入 = 流量 × 转化率 × 单价`、`人日 = 人数 × 工期 × 效率`

   维度互不重叠；重叠必然导致跨维度跳跃。
2. **定语法**——逐边判定「必要／充分／挂起」，不允许含糊的「相关」。
3. **配对完整**——每个节点必须完整分叉到**所有格**。没分叉的格＝漏掉的根。
4. **挂起也是结论，且必须可恢复**——结尾必须报挂起表。**禁止删除**：删掉的枝有根，只是被判为"不是根"。说「X 不是根，因为 …，除非 …」与说「X 是根」同等重要。

## 跳步规则：链可省，格子不可省

轴选对时，**每一格的根就是格子的名字本身**（按定义），中间因果链只是填充解释，可以省略——这就是"第一步即到最宏观的根"。

但前提是格子成立：**省掉的只能是因果链，不能是格子**。轴错了，跳步就是猜。

## 回溯根源：三层缺一不可

回溯根源 ＝ 「问题产生的背景或现象」＋「提问者想解决自己的什么现象」＋「问题本身的根源」。

其他两层可以在逻辑通顺的情况下被其中一层覆盖或包含，从而得到真正的"根源"。多维度时各自独立回溯到根，再由汇合层合并。

## 分类与分层：三判据

任一套轴，缺一即错：

1. **正交**——任取两格，A 格的根不能同时解释 B 格的现象。
2. **可生成**——能用一句话写出「为什么这一格必然存在」。写不出＝这是列举，不完备。
3. **可观测**——每格能用一句话说出「这里出问题时看到什么症状」。说不出的格子不是经验对象，只是名词。

### 生成轴的两个来源（照此取，不要凭灵感取）

| 来源 | 取法 | 例 |
|---|---|---|
| **必经时序** | 按过程每一步切，一步一格 | Windows 服务启动：SCM 注册 → 令牌与窗口站 → PE 加载器 → `DllMain` → 注入与钩子 → 就绪检查 → 受限令牌／完整性 |
| **恒等式** | 按等号右边的因子切 | 收入 ＝ 流量 × 转化率 × 单价；人日 ＝ 人数 × 工期 × 效率 |

### 三个反例（这些都是"列举式"，都不合格）

- 启动失败按「权限／环境／DLL／杀软／配置」切 —— 杀软注入本身就是 DLL 加载，重叠；且没列到的永远想不到。
- 留存低按「新用户／老用户／某渠道」切 —— 这是把人分层，不是把原因分类；「新用户」与「某渠道」还重叠。
- 请求变慢按「前端／后端／数据库／网络」切 —— 一次请求同时经过多个组件，跨维度。

### 社会学问题的取轴

先按阶级／地位／身份／性别把涉及的人分类，再对事情本身分类。理由：社会现象的解释变量常是**位置**而非个体，先切位置才能暴露「同一位置的人行为一致」这层因果。

但守住同层排斥：「他是工人」（位置）与「他想多挣钱」（动机）不同层，混用会得出「工人就是想多挣钱」这种把结构问题个体化的伪根。

### 三种分层方式的选用判据

| 目标 | 分层方式 | 理由 |
|---|---|---|
| 找根、定位故障 | **因果联系**（箭头向上） | 要的是"谁导致谁" |
| 判断"这条能不能解释" | **必要／充分条件** | 最省算力、最抗辩：证一条必要条件不成立，整枝倒 |
| 排进度、排调查顺序 | **前置／后续关系** | 要的是"先查什么"，不是"为什么" |

## 排序取代剪枝

不删任何枝，但必须排序。每个候选根记三个量：

| 量 | 含义 | 取值 |
|---|---|---|
| **份额 Share** | 能解释已观测现象的比例 | 唯一／主因／共因／次要／无 |
| **可控性 Lever** | 知道了能不能动它 | 改配置／换组件／花钱绕／不可控 |
| **证伪代价 Cost** | 排除它要花多少 | 一个重启／一次采样／一笔采购 |

按 `Share × Lever ÷ Cost` 排序，取前 N 条去验证，其余全部留在挂起表。

## 风险与对策（降维损失的账本）

1. **易忽略旁支路径** → 先用生成式轴把格子铺满，再逐格判定；**不删除**，只挂起；结尾交挂起表。
2. **单根树易跨维度跳跃** → 用独立子树在结构上隔离不同维度，不靠自律。
3. **分支爆炸** → 严格沿生成式轴分类，不随意扩展维度；**唯一合法的减法是折叠**（父节点一行 + 子项清单），信息量不减、字符量减。
4. **过度分解** → 维度超过 4 个先合并同源维度；分解带不来新的独立性就是纯开销。
5. **全空列判据** → 所有格子都空而问题仍在 ⇒ **坐标系错误**，换轴重切。这一条是"第一步即到最宏观根"的正确用法：不是跳过中间直接报根，而是看哪一整列全空。

## 与其他两张图的关系

未知在**因果深度**→林状图；未知在**选项广度**→网状图；未知在**数量关系**→公式图。
复杂问题按 林状图 → 网状图 → 公式图 联用：先定因果骨架，再穷举选项，最后定量收敛。

## 输出骨架

```
[🌳 林状图] [选择理由]
轴（生成源：时序 / 恒等式）：<格子清单 + 每格的可观测症状>
逐格回溯：<格 → 根 / 判定为不是根>
汇合层：<多根合并 + 各自的 Share / Lever / Cost>
候选根排序：<按 Share × Lever ÷ Cost>
挂起表：<分支 / 判定 / 依据 / 恢复条件>
结论：<从根解决的动作>
```
